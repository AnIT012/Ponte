# 仮で決めたことの一覧（承認済み）

**全部おすすめ通りで承認された（2026-09-23）。** 仕様書 11.5 章に★として書き写した。「別紙」と書いた項目は REVIEW.md の対応で直した。

実装を進めるために、仕様に書いてない所を仮で決めたもの。元の細かい話は `docs/design/QUESTIONS_v0.1.md` と `QUESTIONS_v0.2.md`。
v0.2 で解決して要らなくなったもの（unknown→tbd、use の削除など）は外した。

**「そのままでいい」ならまとめて OK をもらえれば、仕様書に★として書き写す。** 変えたいものだけ番号で言ってください。

## 言語の意味

| # | 何を | 今の仮 | 私のおすすめ |
|---|---|---|---|
| 1 | `within 3 days` の数え方 | 暦日。3日後の日付の終わり（23:59）まで。過ぎたものは入らない | このまま（実験で自然文が一番間違えた所。言語が1つに決めている価値が大きい） |
| 2 | `days until` | 日付だけで数える。今日なら0、過ぎていればマイナス | このまま |
| 3 | 年の無い日時（monthday） | 年は推測しない。比べる時だけ「今の年」で読む | このまま。年をまたぐ締切（12月に1月の締切）は tbd にさせる仕組みを別に考えたい |
| 4 | `sort` の向き | 昇順だけ | `sort deadline desc` を足したい（別紙 REVIEW） |
| 5 | do の答え | どこからも使われていない行がちょうど1つ | このまま |
| 6 | action が missing（値の無い状態）を返した時 | 「決められなかった」として else へ | このまま |
| 7 | action の else と relate の else | どちらか1つあれば通る。両方あればエラー | このまま |
| 8 | 矛盾する move の `>` が要る条件 | flow に分かれ道があれば必須（画面の flow scene は除く） | このまま |
| 9 | 入れ子の定義 | where に and / or / カッコ、match の中に match、子を持てない節の下の行、group の中の group | このまま |
| 10 | when の閉じたリスト | 仕様の形＋画面の出来事（taps など）＋`user does 〇〇` | `user does` は自由すぎるので消したい（別紙） |
| 11 | until の上限の形 | `N times` か `N 時間 passed` | このまま |
| 12 | `why` | 任意 | このまま（書けば AI の中身が良くなるが、強制はしない） |
