# 仕組み（`ponte/` の中）

`ponte/` は Python 3.11 の標準機能だけで書いています。

```
 .ponte ──parser──▶ 木（見出しと節） ──checker──▶ エラー32種・警告
                        │
                        ├──examples──▶ example と never を流す → 穴さがし
                        │
                        ├──fill──▶ AIに action の中身を書かせる ⇄ 確かめて問題を返す
                        │
                        └──runtime──▶ 実行エンジン ──server + page.html──▶ ブラウザの画面
```

## ファイル

| ファイル | すること |
|---|---|
| `parser.py` | 行の字下げから木を作る。行頭が見出し（thing / rule …）、字下げが節になる。`#` はコメント、`##` は止めるコメントで、`#4F46E5` のような色は値として読む。`use` で別ファイルを、`use std/…` で標準ライブラリを読む |
| `checker.py` | エラーを探す。1つの検査が1つの関数になっている（`ALL_CHECKS`）。E32 の型は、rule ごとに this が何の thing かを推論して確かめる |
| `forms.py` | rule の when、do、値の書き方の一覧。チェッカーも説明もここから作る |
| `body.py` | action の中身（do と shape）を動かす。`TOOLS` が道具の一覧で、説明、エラーの一言、仕様書の表もここから作る |
| `confirm.py` / `report.py` | `with` と `confirm`。report.py は下の層が実際に使った値を報告する小さな部品で、Ponte のほかの部分に依存しない |
| `job.py` | `job` を走らせる。with を引数にし、報告された事実を confirm・require・suspect と照合する |
| `model.py` | `model` を読み、学び、使えるかを決める（仕様 5章 model の決まりどおり）。学んだ結果は `仕様.ponte.models/` に置く |
| `nn.py` | 小さなニューラルネット（全結合、ReLU、softmax、Adam）。標準機能だけで書き、同じデータなら同じ重みになる |
| `ir.py` | check を通った仕様を IR（JSON）にし、共通テストを作る。IR から仕様に戻せる（[IR.md](IR.md)） |
| `examples.py` | example を実行エンジンで流す。`holes()` が穴さがしをする |
| `runtime.py` | 実行エンジン。レコードごとに鍵を1つ持ち、別々のレコードへの操作は並列に進む。flow、who、relate、通知、取り消しを扱う。保存は JSONL への追記で、読み直すと同じ中身に戻る |
| `server.py` | 標準の http.server を使う。画面の組み立て（scene から部品の JSON を作る）、入力の検査、リアルタイム更新（SSE）、`--reload` の入れ替えを受け持つ |
| `auth.py` | `ponte run --login` のログイン。合言葉は hashlib.scrypt で保存する。鍵は HttpOnly の cookie で、メモリにだけ持つ |
| `errors.py` | エラーの辞書（なぜ止めるか、どう直すか）。`ponte explain`、`check --json`、仕様書 13章、ホームページはここから作る |
| `page.html` | 画面そのもの。ライブラリを使わない素の HTML / CSS / JavaScript で、ダークモード、スマホ、英語に対応する |
| `fill.py` | AI に中身を書かせる。SDK は使わず、urllib で API を呼ぶ。書いた中身は example と never で確かめ、通らなければ問題を返して書き直させる |
| `guide.py` | AI への書き方の説明を、`TOOLS`、`forms.py`、std から作る（`ponte guide`） |
| `fmt.py` | 整形する。見た目の幅でそろえ、意味が変わる場合は書き換えない |
| `build.py` | 1つの .pyz にまとめる。std も含める |
| `values.py` | 日時と期間を読み書きする |
| `icons.py` | 画面のアイコンを持つ |
| `doc.py` | `ponte doc`。仕様を1枚の HTML にまとめる |
| `lsp.py` | `ponte lsp`。エディタ向けの言語サーバー。標準入出力で JSON-RPC をやりとりし、check、errors、TOOLS を使う |
| `cli.py` | コマンドを受け付ける |
| `std/` | 標準ライブラリ。中身も Ponte で書き、example を付けている |

## 実装の原則

- **一覧は1か所にだけ置きます。** 道具は `body.TOOLS`、rule の書き方は `forms.py` にあります。エラーは `errors.ERRORS`、機械で確かめる never は `fill.MACHINE_NEVERS` にあります。説明、エラー、仕様書の表、ホームページはそこから作ります。ずれるとテストが失敗します（`tests/test_guide.py`、`test_errors.py`、`test_docs.py`）。
- 年は推測しません。年のない日付は、年のないまま持ちます。「今より前」になる締切は、画面で聞き返します。
- 書いていないことは誰もできません。who にない操作は、画面のボタンを出さないか、押せないようにします。
- example が通っても、確かめていない部分は示します。これが `ponte test` の穴さがしです。

## テスト

`python -m pytest` で流します。320件ほどあり、10秒ほどで終わります。

| ファイル | 確かめること |
|---|---|
| `test_checker.py`、`cases/` | エラーごとの「壊した仕様」と「直した仕様」の組（`make_cases.py` で作る） |
| `test_types.py` | 型（E32）。わざと壊した12通りを止めること |
| `test_engine_fuzz.py` | エンジンにでたらめな操作（40通り×60操作）をして、flow、who、通知先、読み直しの約束が守られること |
| `test_guide.py` | 道具の例がすべて動くこと、仕様書の表と実装がずれていないこと |
| `test_docs.py` | 入門の出力が本物であること、見本のアプリがすべて通ること、ホームページが docs と実装から作ったものと同じこと |
| `test_errors.py` | check が出すエラーがすべて辞書にあること、`explain` と `check --json` |
| `test_auth.py` | ログイン。本物のサーバーを立て、cookie、合言葉、登録、間違いが続いた場合、外に開くときの止め方を確かめる |
| `test_std.py` | 標準ライブラリ |
| `test_runtime.py`、`test_spec_gaps.py`、`test_ui_language.py` | 実行エンジン、サーバー、画面 |
| `test_lend.py` | 役割、取り消し、2つの thing |
| `test_fill.py`、`test_experiment_v2.py` | AI による穴埋めのループ、実験の採点 |
