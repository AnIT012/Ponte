# 人とAIの間の言語 — 仕様 v0.2（名前未定）

v0.1 と、その後の相談で決めたことを全部まとめたもの。
★は確定。v0.2 で新しく決めたものには（v0.2）と付けた。

---

## 0. コンセプト ★

人とAIの間の言語。**人は決めて、AIが書いて、言語が守る。**

- 今までの言語は「人と機械の間」で、どうやるかを書いた。
- この言語は「人とAIの間」で、何が欲しいか・何がダメか・何がまだ決まってないかを書く。
- この言語で書いたものが、そのまま動くプロダクトになる。Python や Go は、アセンブリのように下に隠れる位置に落とす。
- if も for も true/false も無い。それは「どうやるか」の道具だから。

**目標（v0.2）**
- 9割は言語の中で自由に書ける。普通のアプリは、画面も含めてこの言語だけで作れる。
- 残りの1割は action の中身に閉じ込める。契約だけ書いて、中身はAIか自分が埋める。

---

## 1. 設計原則 ★

1. **パーツは少なく、1パーツ1仕事。** 複雑さはパーツを増やさず、組み合わせで出す。
2. **何を（必須）／どうやるか（任意）。** どうやるかは how と style にだけ書ける。書かなければAIが決める。書いたらその通りにしか作れない。
3. **順序を書かない。** 並列が標準。thing 1件＝1つの独立した箱。箱をまたぐ処理は全部並列、同じ箱の中は1つずつ。順序が要る時は flow（状態）か relate（ルールの関係）で表す。
4. **決めてないことはエラー。** 曖昧なまま渡せない。
5. **入れ子禁止、名前を付けて積む。** 条件の中に条件を書かない。名前を付けて段階的に作る。
6. **何でも作れる、危ないことは箱の中に閉じ込める。** 外側（要件と契約）は絞る。内側（action の中身）は契約を守れば何でもあり。
7. **同じ意味の語は1つだけ（v0.2）。** else はどこでも「逃げ道」、do はどこでも「やること」、`>` はどこでも「ぶつかったらこっちが勝つ」、`|` はどこでも「どれか1つ」。

## 2. 型 ★

| 型 | 意味 |
|---|---|
| text | 文字 |
| number | 数 |
| count | 0以上の整数（v0.2） |
| money | お金。通貨付き、小数の誤差なし。`money yen`（v0.2） |
| percent | 割合（v0.2） |
| date | 日時 |
| monthday | 年の無い月日と時刻。`10/15 12:00`（v0.2） |
| duration | 期間。`3 days` `5 seconds` |
| file / image / pdf | ファイル（v0.2） |
| `[a \| b \| c]` | 決まった状態のどれか1つ（v0.2。旧 `one of [a, b, c]`） |
| 箱の名前 | 別の箱を1つ指す。`owner User`（v0.2。旧 `ref User`） |
| `list of 箱の名前` | 別の箱を複数指す（v0.2。旧 `many`） |

- **true / false は無い。** `done[todo | done]` のように、全部名前の付いた状態にする（if を生ませないため）。
- 組み込みの値: `now`、`me`（今使っている人。旧 current user）。

## 3. 記号とコメント（v0.2）

| 記号 | 意味 | 使う所 |
|---|---|---|
| `\|` | または（どれか1つ） | 状態、flow の分かれ道、出力、match の左側 |
| `->` | 移る・対応する | flow、match、example |
| `>` | ぶつかったらこっちが勝つ | flow、relate |
| `[ ]` | 状態を並べる | 状態の宣言だけ |
| `{ }` | 取り出した値 | user says など |
| `#` | 普通のコメント | どこでも。ビルドに関係無い |
| `##` | 止めるコメント | 1つでも残っていたらビルドできない |

- **and の記号は無い。** and は行を重ねて書く（where を2行書けば両方満たす）。
- **`##` の使い方。** AIが仕様の穴に気づいたら、答えの案を `##` で書き、理由を後ろの `#` に書く。人は `##` を外せば承認、行ごと消せば却下。人が「後で必ず見直す」印に使ってもいい。

```
list DueSoon
  of    Application
  where status is draft
  where deadline within 3 days
  ## where deadline is after now    # 締切が過ぎた応募も通知する？
```

## 5. 各パーツ

### thing ★ — データの形（v0.2。旧 entity）
```
thing Application
  company   Company   gone[block]
  deadline  date
  owner     User      gone[remove too]
  memo      text
  status[draft | submitted | passed | failed]
```
- 1件が1つの「箱」。箱の中の書き換えは1つずつ処理される。
- 項目は `名前 型` を並べるだけ。`:` は付けない。名前と型は色分けで見分ける（v0.2）。
- 状態は `名前[a | b]`（v0.2）。
- 別の箱を指す項目には、指した先が消えた時どうするかを `gone[...]` で必ず書く（v0.2。7.3）。

### flow ★ — 状態の流れ
```
flow Application.status
  draft -> submitted -> passed | failed
  failed > passed
```
- `->` の通りにしか動けない（draft から passed に飛べない）。
- flow で管理する項目は move でしか変えられない。set 禁止。
- **`failed > passed`**: 同じ箱に矛盾する move が同時に来た時の勝者（v0.2。旧 `on conflict failed wins over passed`）。同時に来うるのに書いてない → エラー。
- flow は「状態の流れ」だけを書く。動作の順番は書かない（v0.2）。

### list ★ — 条件で絞った集まり
```
list DueSoon
  of    Application
  where status is draft
  where deadline within 3 days
  sort  deadline
```
- where を複数行 → 全部満たす（and）。1行の中に and / or / カッコは書けない。
- list から list を作れる（積み重ね）。循環参照 → エラー。
- for の代わり: ルールや通知は「当てはまるもの全部」に効く。
- `within 3 days` は暦日で数える。今から3日後の終わりまで（v0.2）。
- `sort deadline desc` で逆の順（新しい順）。書かなければ昇順（v0.2）。
- v0.2 で `from` → `of`、`sort by` → `sort`。

### match ★ — 値ごとの結果
```
match Application.status to color
  draft     -> red
  submitted -> gray
  passed    -> blue
  else      -> gray
```
- 旧 `otherwise` は `else` に揃えた（v0.2）。
- else が無いとエラー。ただし、宣言された状態を全部書いた match は else を省略できる（v0.2）。
- 宣言に無い状態を左側に書いたらエラー（打ち間違いを止める。v0.2）。
- 左側は `|` でまとめられる: `saturday | sunday -> weekend`。
- match の中に match は書けない（入れ子）。

### rule ★ — きっかけ → やること
```
rule Remind
  why   締切を落とさないため
  when  every day at 21:00
  do    notify owner each of DueSoon
  example
    given   Application
      company   "Osaka Gas"
      deadline  "9/24 23:59"
      status    draft
    at      "9/21 21:00"
    expect  notify "Osaka Gas"
```
- 旧 because は why（v0.2）。任意。
- **when は出来事だけ。** 状態は where に書く（`when deadline within 3 days` は禁止）。
- when に書ける出来事（閉じたリスト）:
  - 時間: `every day at 21:00` / `every monday at 9:00` / `at 9/24 23:00`
  - 人: `user says "..."` / `user taps X` / `user holds X` / `user swipes X left` / `user drags X to Y` / `user types in X` / `user opens Scene` / `user leaves Scene`（v0.2 で画面の出来事を追加）
  - データ: `〇〇 is created` / `〇〇 moves to 状態` / `〇〇 is removed`
  - 外: `Gmail gives new message`（connect の gives。v0.2）
- `{...}` で取り出した値は変数になる。対象の箱は必ず絞る:
  `when user says "submitted {company}"` → `do move Application where company is {company} to submitted`
- 画面で押された1件は `this` で指す: `do move this to submitted`（v0.2）。
- ルール同士の関係は relate に書く（v0.2）。
- **do は1つだけ（v0.2）。** 2つやりたい時は rule を分けて、relate の `then` でつなぐ。
- **通知は宛先を書く（v0.2）。** `notify me "..."`（きっかけの人）、`notify owner each of DueSoon`（それぞれの箱の owner が指す人）。
- flow の状態ごとにルールを書いていて抜けがある → 「passed のときは？」と警告。

### relate — ルール同士の関係（v0.2）
```
relate
  ReadMail     then    FileMail
  ManualAdd    then no FileMail
  CheckSpam    before  FileMail
  NotifyFailed >       Remind
  LineNotify   else    MailNotify
```
全部の行が「左が先、右が後」。

| 書き方 | 意味 |
|---|---|
| `A then B` | Aが終わったらBが動く |
| `A then no B` | Aをやったら、この後Bは動かない。Bがもう済んでいても取り消さない |
| `A before B` | Bが動く時、Aは済んでいる。Aが終わってもBは勝手に動かない |
| `A > B` | 同時に当てはまったらAが勝つ |
| `A else B` | Aが失敗したらBをやる |

- `A then B` の途中で落ちても、言語が裏で「この箱で A は済んだ」を記録するので続きからやれる。
- action にも else があり、relate でも同じ action に else がある → エラー（逃げ道は1つだけ）。

### action ★ — 中身が空の箱（契約だけ書く）
```
action ExtractDeadline
  in      mail text
  out     found monthday | missing
  example "10/15(木)12:00まで"            -> found 10/15 12:00
  example "【締切9/24 23:59】"            -> found 9/24 23:59
  example "来週中にご提出ください"        -> missing
  example "9/24 23:59 または 9/30 23:59"  -> missing
  never   guess the year
  else    ask user
  by      ai
  how
    limit 5 seconds
```
- 旧 input / output は in / out（v0.2）。
- example 最低2つ必須。中身は例を全部通らないと採用されない。
- else 必須: 自信が無い時の逃げ道（`ask user` / `use default ...` / `skip`）。
- **契約の矛盾はエラー（v0.2）。** example の答えが out の型に合わない、never と out の型がぶつかる（`never guess the year` なのに out が年の要る date）など。
- **機械が確かめる never（v0.2）。** 次の never は、中身ができた時に機械が大量の入力で確かめる。それ以外の never は、今は機械では確かめられない（AIへの指示にはなる）。

| never | 確かめ方 |
|---|---|
| `guess the year` | 例の入力と、年の無い入力をいくつか流して、答えに年（4桁の数）が出ないか |
| `depend on width` | 例の入力を全角にして流し、半角の時と同じ答えになるか |
| `return empty` | 例の入力とおかしな入力を流して、値が空の答えを返さないか |
| `fail` | おかしな入力（空・長すぎる・絵文字・ありえない日付など）でも止まらないか |
- 失敗や「見つからない」も out の状態で表す（`found ... | missing`）。

**by ― 誰が中身を埋めるか ★（v0.2 で ask ai を追加）**

| 書き方 | いつ | 中身 |
|---|---|---|
| `by ai`（標準） | ビルドの時に1回 | AIが do を書いて固定する。人も読めて直せる |
| `ask ai` | 実行の度に毎回 | AIに聞く。do は無い。how に時間かお金の上限が必須 |
| `by code "extract.lang"` | — | 自分で書いた do |
| `by Gmail` | 実行の度に | connect 先がやる |

誰が埋めても、同じ example・never・else で検証される。

**do ― action の中身（v0.2）**
```
  do
    text  = normalize mail
    hits  = find all Deadline in text
    kind[one | none | many] = match count of hits
                                1    -> one
                                0    -> none
                                else -> many
    found = match kind
              one  -> found monthday of first of hits
              none -> missing
              many -> missing
```
- 書けるのは `名前 = 式` と、名前を付けた match だけ。
- **答えは「他のどの行からも使われていない行」。** ちょうど1つでなければエラー。答えの行に `[...]` は要らない（形は out に書いてある）。書いた場合は `answer[found monthday | missing]` のように out の形と同じにする。
- 一時的な状態は `名前[a | b] = match ...` で宣言して使う。
- 書き換え・ループ・再帰・true/false は無い。だから必ず止まる。
- 順番は名前の依存関係で決まる。上から順に実行されるわけではない。
- 使える道具は 10章。

**shape ― 文字の形（v0.2。正規表現の代わり）**
```
shape Deadline
  month  digits 1..2
  "/"
  day    digits 1..2
  maybe  "(" any 1 ")"
  maybe  space
  hour   digits 1..2
  ":"
  minute digits 2
```

### how ★ — どうやるか（任意）
- rule と action の中にだけ書ける。
- 書かなければAIが決める。書いたらAIはその通りにしか作れない。
- 例: `check every 10 minutes` / `limit 5 seconds` / `limit 1 yen` / `on failure retry 3 times` / `repeat ... until 〇〇 or 1 hour passed`
- until は回数か時間の上限必須。無いとエラー（無限ループ防止）。

### group — まとまり（v0.2）
```
group Mail
  rule ReadMail
    when  Gmail gives new message
    do    ExtractDeadline

  rule FileMail
    do    create Application

  relate
    ReadMail then FileMail
```
- 名前で括るだけ。継承は無い。外からは `Mail.ReadMail` で呼ぶ。
- group の中の字下げは入れ子と数えない。group の中に group は書けない。
- 別ファイルの group は `use "mail.lang"` で使う。

### tbd ★ — まだ決めてないこと（v0.2。旧 unknown）
```
tbd
  timezone of deadline
  who can delete Application
```
- 残っているとビルドできない。AIは埋めずに質問してくる。
- `##` との違い: tbd は答えが無い。`##` は答えの案がもう書いてある。

### never ★ — やってはいけないこと
- action の中にも、ファイル全体にも書ける。
- 生成されたコードのガード＋テストになる。証明できる違反はビルド前にエラー。
- action の never は、自動で作った大量の入力で検証する（例: 年の無い入力を何百個も作り、全部 missing か else になるか確かめる）。

## 6. 画面（v0.2）

「何を見せるか」を scene・look・part・input に、「どう見せるか」を style に書く。書かなかった見た目はAIが決める。

### scene — 場面
```
scene Home
  menu[open | closed] = closed
  top     Header
  main    match count of DueSoon
            0    -> EmptyNote
            else -> DueSoon as cards
  side    Application as list
  bottom  button add
  over    match menu
            open   -> Menu
            closed -> nothing
```
- 置き場所は `top` / `main` / `side` / `bottom` / `over`（上に重ねる）。細かく並べる時は `row` / `column` / `grid 3`。
- 出し分けは match。`nothing` は何も出さない。
- 画面だけの状態は `名前[a | b] = 最初の値`。

### 画面の移動
```
flow scene
  Home -> Detail -> Edit
  Home -> AddApplication

rule OpenDetail
  when  user taps card on DueSoon
  do    go Detail with this
```
- flow scene の矢印の通りにしか移動できない。矢印に無い移動はエラー。

### look — 見せ方
```
look DueSoon as cards
  title   company
  sub     DeadlineBadge of deadline
  mark    color of status
  button  submitted-button named 提出した

look Header
  button menu-button   named メニュー  toggle menu
  button close-button  named 閉じる    set menu closed
```
- 見せ方の種類: cards / list / table / detail / input / calendar / board / chart / tabs / dialog / sheet / toast / map / media
- board は flow から状態ごとの列が自動でできる。カードを動かすと move の出来事が起きる。
- **画面だけの状態は look の中で `toggle 状態` / `set 状態 値` と書ける。** rule は要らない。データ（thing の項目）は rule の move でしか変えられない。

### part — 自分で作る部品
```
part DeadlineBadge
  in    deadline monthday
  do
    left = days until deadline
    urgency[today | soon | later] = match left
      0    -> today
      1..3 -> soon
      else -> later
  show  text "あと{left}日"
  mark  urgency
```
- 名前を付けて、どこでも使い回せる。
- part の中で part を使うのは可。part の中で part を定義するのは不可。
- 言語の見せ方で描けない絵は `part 名前 by ai`。example で「このデータの時にこうなっているか」を検証する。見た目の良し悪しまでは機械で検証できない。

### input — 入力
```
input AddApplication
  company   required
  deadline  required, from now
  memo
  resume    file, pdf only, max 5 MB
```
- 送ったら `Application is created` の出来事が起きる。
- 入力のチェックは項目の隣に書く。満たさない時の表示は言語が出す。

### style — 見た目
```
style theme
  color main  #2F6FEB
  space s     8

style DueSoon
  card     round 12, shadow soft, pad 16
  title    size 18, bold
  mark     dot left
  gap      16
  enter    fade 200ms
  reorder  slide 150ms

style Home on phone
  main  column
style Home on wide
  main  grid 3
```
- 色・大きさ・余白・角丸・影・フォント・動き・並べ方まで書ける。
- 画面の大きさは `on phone | tablet | wide`。
- 書かなかった所はAIが決める。

### words — 画面の文字と多言語
```
words ja
  add  追加
words en
  add  Add
```
- 片方の言語だけ訳が無い → エラー。
- **words がある spec では、画面の文字は words の名前で書く（v0.2）。** ボタンの名前・見出し・空の時の文・確認の文・部品の文・部品が計算する文が対象。words に無ければエラー（25）。日本語は words ja に1回だけ書く。
```
look DueSoon as cards
  heading  due-heading
  button   submitted-button named submit icon send

words ja
  due-heading  3日以内に締切
  submit       提出した
words en
  due-heading  Due within 3 days
  submit       Mark submitted
```
- 言語が出す文字（`search` `save` `cancel` `none`）も words で訳せる。
- words が無い spec は、画面の文字をそのまま書ける。

### 読み上げ対応
- 名前の無いボタン（`named` が無い）、説明の無い画像（`about` が無い）は、試作の間は注意、公開する時はエラー。

### 画面のための追補（v0.2 UI）★
画面を作り込む時に足した小さな部品。どれも1つの仕事だけ。

| 書き方 | 意味 |
|---|---|
| `main  tabs tab` | 画面の状態 `tab[...]` を切り替えるタブを出す |
| `main  this as detail` | 前の画面で押された1件を詳しく見せる |
| `look Application as detail` | thing の名前の look は、詳しく見せる時の見せ方 |
| `empty "..."`（look の中） | 1件も無い時に出す文 |
| part の中の `do` | 部品の中で値を計算する。action の中身と同じく `do` の下に `名前 = 式` と `名前[a \| b] = match ...` |
| `days until X` | 今日から X までの日数（今日なら 0、過ぎていればマイナス） |
| match の左の `1..3` / `..-1` / `4..` | 数の範囲（両端を含む） |
| `match 部品名.状態 to color` | 部品の状態ごとの色 |
| ボタンの行の `tone main \| quiet \| good \| danger` | ボタンの強さと色（`button failed-button named 不合格 tone danger`）。書かなければ一覧の最初のボタンと画面の下のボタンだけ強い |
| `#4F46E5` | `#` のすぐ後ろに16進の色が続く時は、コメントではなく色の値 |
| `user taps X on 箱の名前` | list の名前でなく thing の名前で書けば、どの一覧・ボード・詳しくから押しても動く |
| `button 名前 named 文字 icon 名前` | ボタンにアイコン。アイコンは組み込みの24個だけ（無い名前はエラー） |
| `button 名前 named 文字 confirm "文"` | 押す前に確かめる。やめれば何も起きない |
| `named "空白を含む 名前"` | 名前は1語。空白を含むなら引用符。ボタンの行に知らない語があればエラー |
| `match Application.status to icon` / `match tab to icon` | 状態ごと・タブごとのアイコン（色の match とは別に持てる） |
| `lead company`（look の中） | 頭文字の丸 |
| `heading "..."`（look の中） | 見出しと件数 |
| `search company, memo`（look の中） | 一覧の検索 |
| `group by status`（look の中） | 状態ごとにまとめる |
| `take 20`（look の中） | 最初に見せる件数。残りは「もっと見る」 |
| `empty "..." button add named 追加`（look の中） | 1件も無い時の文と、次にやることのボタン |
| `top  notices` | お知らせのベル（未読の数と一覧） |
| `go EditApplication with this` | input を with this で開くと、その1件の編集。状態の項目は書き換えられない（move だけ） |
| words の `"引用符の鍵"  訳` | spec にそのまま書いた日本語も訳せる |

言語が画面を守るもの:
- **flow で動けないボタンは、自動で押せなくなる。** rule が `move this to X` で、いまの状態から X へ動けなければ、そのボタンは薄くなって押せない。
- **board でカードを動かすと move が起きる。** flow に無い流れは「『下書き』から『通過』へは動かせません」と断られる。
- 画面の下（bottom）のボタンだけが目立つ色。上や一覧のボタンは控えめ（最初のボタンだけ強い）。
- look の title / lead / search / group by に無い項目名、無いアイコン名、読めないボタンの行はエラー（28）。

### リアルタイム
- 何も書かなくても画面は常に最新。箱が変わったら、それを見せている画面が自動で変わる。

## 7. データと人（v0.2）

### 7.1 who — 誰が何をできるか
```
who
  user   can see    Application where owner is me
  user   can change Application where owner is me
  admin  can do     everything
  nobody can remove Application
```
- 書いてないことは誰もできない。
- who が1行も無い thing → エラー。
- rule も who に従う。user says や user taps で動く rule は、その人ができることしかできない。
- ログインの方法は connect に任せる。

### 7.2 保存
- 保存は言語が持つ。thing を書けばデータは残る。何のDBかは書かない。

### 7.3 消した時の扱い
- 他の箱を指す項目には `gone[...]` を必ず書く。無ければエラー。

| 書き方 | 意味 |
|---|---|
| `gone[remove too]` | 一緒に消す |
| `gone[leave empty]` | 空にする |
| `gone[block]` | 指されている間は消せない |

### 7.4 thing を変えた時
```
change Application to v2
  add     memo text = ""
  rename  company to corp
  remove  owner
  remove  state passed -> failed
```
- thing の形が前回のビルドと違うのに change が無い → エラー。
- 足した項目の初期値が無い → エラー。
- 状態を消す時は、その状態だった箱の移し先が必須。

## 8. 外とつながる（connect）（v0.2）
```
connect Gmail
  gives   new message  Message
  does    send mail    to text, body text -> sent | failed
  needs   key GMAIL_TOKEN
  limit   100 per hour
```
- `gives`: 向こうから届く出来事。`when Gmail gives new message`。
- `does`: こちらから頼めること。結果は必ず状態。
- `needs`: 秘密の値。値そのものは仕様に書かず、実行する時に渡す。
- `limit`: 回数の上限。
- does の失敗の逃げ道（relate の else か、結果を match して書く）が無い → エラー。
- **依存ゼロ:** 言語の中は依存ゼロ。外との境界は connect に宣言した口だけ。

## 9. テスト（example）（v0.2）
```
rule MarkSubmitted
  when  user says "submitted {company}"
  do    move Application where company is {company} to submitted
  example
    given   Application
      company  "Osaka Gas"
      status   draft
    given   Application
      company  "Other"
      status   draft
    says    "submitted Osaka Gas"
    expect  Application is submitted
      company  "Osaka Gas"
    expect  Application is draft
      company  "Other"
```
- 3段: `given`（前の状態）→ 出来事 → `expect`（結果）。
- **箱の中身は字下げして1行1つで書く（v0.2）。** `given Application` の下に `company "Osaka Gas"` のように並べる。カッコと `,` は使わない。
- 出来事: `at "..."` / `says "..."` / `taps X on 箱の名前`（下に中身）/ `taps X on 画面の名前` / `gets Gmail new message "..."`
- 結果: `expect notify "..."` / `expect X is 状態` / `expect scene Detail` / `expect Home shows 2 cards` / `expect nothing`

## 10. do で使える道具（v0.2）

| 種類 | 道具 |
|---|---|
| 文字 | length, trim, lower, upper, normalize（全角半角）, split, join, replace, find all Shape, starts with, contains |
| 数 | sum, min, max, avg, round, abs |
| 日時 | weekday of, days until, add 3 days, date of, time of, start of day, end of day, monthday of |
| 集まり | count of, first of, last of, each, sort, group by, unique, take 3 |
| 読み書き | read json, write json, read csv, write csv, text of pdf, size of image |

- each と sort は数に上限がある集まりにだけ使える。
- 足りない計算は action の by ai / by code に押し込む。
- 通貨の違う money を足したらエラー。

## 11. 実行モデル ★
- 箱＝アクター。thing 1件ごとに独立。Erlang / Go の goroutine＋channel と同じ思想。
- ルールは全部独立。並列を書かなくても並列。
- 同じ箱への書き換えは届いた順に1つずつ。矛盾は flow の `>` で決める。
- ルール同士の順番と強さは relate で決める（v0.2）。
- 画面は箱の変化を受けて自動で変わる（v0.2）。
- **実行するもの（v0.2）:** 自前の実行エンジンで spec を直接動かす。その後 WebAssembly に直接変換する。Go など他の言語やライブラリには依存しない。

---

## 11.5 確定した細かい決まり ★（v0.2、DECISIONS から）

| 何を | 決まり |
|---|---|
| `within N days` | 暦日。N日後の日付の終わり（23:59）まで。過ぎたものは入らない |
| `days until X` | 日付だけで数える。今日なら0、過ぎていればマイナス |
| monthday | 年は推測しない。比べる時だけ今の年で読む |
| do の答え | どこからも使われていない行がちょうど1つ |
| action が値の無い状態（missing など）を返した | 決められなかったとして else へ |
| 逃げ道 | action の else か relate の else のどちらか1つ。両方はエラー |
| `>` が要る時 | flow に分かれ道があれば必須（flow scene は除く） |
| 入れ子 | where の and / or / カッコ、match の中の match、子を持てない節の下の行、group の中の group |
| until の上限 | `N times` か `N 時間 passed` |
| why | 任意 |
| 人がきっかけでない rule | who に縛られず仕組みとして動く。人がきっかけの rule はその人の who に従う |
| input で作った箱の User の項目 | 作った人 |
| thing の形 | `check --save-shape` で残し、次から比べる |
| 編集 | input を `with this` で開くと編集。状態は書き換えられない（move だけ） |
| タップ | `user taps X on 箱の名前` ならどの一覧・ボード・詳しくから押しても動く |
| ボタンの名前 | 1語。空白を含むなら引用符 |
| 画面の状態 | ブラウザ側、見ている人ごと |
| 読み上げ対応の漏れ | 試作は注意、公開はエラー |
| AIの中身の置き場所 | `x.lang.ai/<action名>.lang`。人の spec に混ぜない |
| `##` の承認 | 外せば承認、行ごと消せば却下 |
| AIの呼び方 | 依存ゼロのため、標準の urllib で API を直接呼ぶ |

## 12. ビルド手順 ★
1. **読む:** 解析
2. **チェック:** 13章のエラーを全部見る。通らないと先に進めない
3. **組み立て:** thing・flow・list・match・rule・relate・scene・look・style はAI無しで決まった変換。毎回同じ結果
4. **穴埋め:** action の中身（by ai）と、style で書かなかった見た目だけAIが決める
5. **検証:** 全部の example と never を流す。通ったら完成、通らなければAIに書き直させる

## 12.5 道具（v0.2）

| 使い方 | すること |
|---|---|
| `python -m lang check x.lang` | 13章のエラーを全部見る。`--publish` で公開する時の検査、`--save-shape` で thing の形を残す |
| `python -m lang test x.lang` | rule と action の example、機械が確かめる never を全部流す |
| `python -m lang fill x.lang` | by ai の action の中身をAIに書かせる。通るまで問題を返して書き直させ、`x.lang.ai/` に残す |

| `python -m lang run x.lang` | 動かす。ブラウザで画面が出る |
| `python -m lang build x.lang -o app.pyz` | spec と中身と実行エンジンを1つのファイルにまとめる。`python app.pyz` で動く |

## 13. エラー一覧（決めてないことはエラー）

**v0.1 から**

## 付録: 就活Hub（メール→締切→通知）を v0.2 で書いたもの

```
thing Application
  company   text
  deadline  monthday
  owner     User   gone[remove too]
  status[draft | submitted | passed | failed]

thing User
  name  text

flow Application.status
  draft -> submitted -> passed | failed
  failed > passed

who
  user   can see    Application where owner is me
  user   can change Application where owner is me
  user   can see    User where it is me

list DueSoon
  of    Application
  where status is draft
  where deadline within 3 days
  sort  deadline

match Application.status to color
  draft     -> red
  submitted -> gray
  passed    -> blue
  failed    -> gray

connect Gmail
  gives  new message  Message
  needs  key GMAIL_TOKEN

action ExtractDeadline
  in      mail text
  out     found monthday | missing
  example "10/15(木)12:00まで"            -> found 10/15 12:00
  example "【締切9/24 23:59】"            -> found 9/24 23:59
  example "来週中にご提出ください"        -> missing
  example "9/24 23:59 または 9/30 23:59"  -> missing
  never   guess the year
  else    ask user
  by      ai

rule ReadMail
  why   メールの締切を自動で拾うため
  when  Gmail gives new message
  do    ExtractDeadline

rule Remind
  why   締切を落とさないため
  when  every day at 21:00
  do    notify owner each of DueSoon
  example
    given   Application
      company   "Osaka Gas"
      deadline  "9/24 23:59"
      status    draft
    at      "9/21 21:00"
    expect  notify "Osaka Gas"

rule MarkSubmitted
  when  user taps submitted-button on DueSoon
  do    move this to submitted
  example
    given   Application
      company  "Osaka Gas"
      status   draft
    taps    submitted-button on Application
      company  "Osaka Gas"
    expect  Application is submitted
      company  "Osaka Gas"

relate
  MarkSubmitted > Remind

scene Home
  top     Header
  main    match count of DueSoon
            0    -> EmptyNote
            else -> DueSoon as cards
  bottom  button add named 追加

flow scene
  Home -> AddApplication

part Header
  show  text "就活Hub"

part EmptyNote
  show  text "3日以内に締切の下書きはありません"

look DueSoon as cards
  title   company
  sub     deadline
  mark    color of status
  button  submitted-button named 提出した

input AddApplication
  company   required
  deadline  required

style DueSoon
  card   round 12, shadow soft, pad 16
  title  size 18, bold

tbd
  timezone of deadline
```

※ 付録は tbd が残っているので、このままでは「渡せません」になる。これは狙いどおり。
