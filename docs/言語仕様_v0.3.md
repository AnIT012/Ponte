# Ponte — 仕様 v0.3

v0.2 と、その後の追補を1つにまとめたもの。中身（決まり）は v0.2 と同じ。
★は確定。

---

## 0. コンセプト ★

人とAIの間の言語。**人は決めて、AIが書いて、言語が守る。**

- 今までの言語は「人と機械の間」で、どうやるかを書いた。
- この言語は「人とAIの間」で、何が欲しいか・何がダメか・何がまだ決まってないかを書く。
- この言語で書いたものが、そのまま動くプロダクトになる。Python や Go は、アセンブリのように下に隠れる位置に落とす。
- if も for も true/false も無い。それは「どうやるか」の道具だから。

**目標**
- 9割は言語の中で自由に書ける。普通のアプリは、画面も含めてこの言語だけで作れる。
- 残りの1割は action の中身に閉じ込める。契約だけ書いて、中身はAIか自分が埋める。

---

## 1. 設計原則 ★

1. **パーツは少なく、1パーツ1仕事。** 複雑さはパーツを増やさず、組み合わせで出す。
2. **何を（必須）／どうやるか（任意）。** どうやるかは how と style にだけ書ける。書かなければAIが決める。書いたらその通りにしか作れない。
3. **順序を書かない。** 並列が標準。thing 1件＝1つの独立した箱。箱をまたぐ処理は全部並列、同じ箱の中は1つずつ。順序が要る時は flow（状態）か relate（ルールの関係）で表す。
4. **決めてないことはエラー。** 曖昧なまま渡せない。
5. **入れ子禁止、名前を付けて積む。** 条件の中に条件を書かない。名前を付けて段階的に作る。
6. **何でも作れる、危ないことは箱の中に閉じ込める。** 外側（要件と契約）は絞る。内側（action の中身）は契約を守れば何でもあり。
7. **同じ意味の語は1つだけ。** else はどこでも「逃げ道」、do はどこでも「やること」、`>` はどこでも「ぶつかったらこっちが勝つ」、`|` はどこでも「どれか1つ」。

## 2. 型 ★

| 型 | 意味 |
|---|---|
| text | 文字 |
| number | 数 |
| count | 0以上の整数 |
| money | お金。通貨付き、小数の誤差なし。`money yen` |
| percent | 割合 |
| date | 日時 |
| monthday | 年の無い月日と時刻。`10/15 12:00` |
| duration | 期間。`3 days` `5 seconds` |
| file / image / pdf | ファイル |
| `[a \| b \| c]` | 決まった状態のどれか1つ（旧 `one of [a, b, c]`） |
| 箱の名前 | 別の箱を1つ指す。`owner User`（旧 `ref User`） |
| `list of 箱の名前` | 別の箱を複数指す（旧 `many`） |

- **true / false は無い。** `done[todo | done]` のように、全部名前の付いた状態にする（if を生ませないため）。
- 組み込みの値: `now`、`me`（今使っている人。旧 current user）。

## 3. 記号とコメント

| 記号 | 意味 | 使う所 |
|---|---|---|
| `\|` | または（どれか1つ） | 状態、flow の分かれ道、出力、match の左側 |
| `->` | 移る・対応する | flow、match、example |
| `>` | ぶつかったらこっちが勝つ | flow、relate |
| `[ ]` | 状態を並べる | 状態の宣言だけ |
| `{ }` | 取り出した値 | user says など |
| `#` | 普通のコメント | どこでも。ビルドに関係無い |
| `##` | 止めるコメント | 1つでも残っていたらビルドできない |

- **and の記号は無い。** and は行を重ねて書く（where を2行書けば両方満たす）。
- **`##` の使い方。** AIが仕様の穴に気づいたら、答えの案を `##` で書き、理由を後ろの `#` に書く。人は `##` を外せば承認、行ごと消せば却下。人が「後で必ず見直す」印に使ってもいい。

```
list DueSoon
  of    Application
  where status is draft
  where deadline within 3 days
  ## where deadline is after now    # 締切が過ぎた応募も通知する？
```

## 4. パーツ一覧

**見出し（行頭に書く）**

**節（見出しの中に字下げして書く）**

**守り（言語が守らせる・赤）**
never, else, `>`, `##`, tbd, who, gone, limit

## 5. 各パーツ

### thing ★ — データの形（旧 entity）
```
thing Application
  company   Company   gone[block]
  deadline  date
  owner     User      gone[remove too]
  memo      text
  status[draft | submitted | passed | failed]
```
- 1件が1つの「箱」。箱の中の書き換えは1つずつ処理される。
- 項目は `名前 型` を並べるだけ。`:` は付けない。名前と型は色分けで見分ける。
- 状態は `名前[a | b]`。
- 別の箱を指す項目には、指した先が消えた時どうするかを `gone[...]` で必ず書く（7.3）。

### flow ★ — 状態の流れ
```
flow Application.status
  draft -> submitted -> passed | failed
  failed > passed
```
- `->` の通りにしか動けない（draft から passed に飛べない）。
- flow で管理する項目は move でしか変えられない。set 禁止。
- **`failed > passed`**: 同じ箱に矛盾する move が同時に来た時の勝者（旧 `on conflict failed wins over passed`）。同時に来うるのに書いてない → エラー。
- flow は「状態の流れ」だけを書く。動作の順番は書かない。

### list ★ — 条件で絞った集まり
```
list DueSoon
  of    Application
  where status is draft
  where deadline within 3 days
  sort  deadline
```
- where を複数行 → 全部満たす（and）。1行の中に and / or / カッコは書けない。
- list から list を作れる（積み重ね）。循環参照 → エラー。
- for の代わり: ルールや通知は「当てはまるもの全部」に効く。
- `within 3 days` は暦日で数える。今から3日後の終わりまで。
- `sort deadline desc` で逆の順（新しい順）。書かなければ昇順。
- `from` → `of`、`sort by` → `sort` になった（16章）。

### match ★ — 値ごとの結果
```
match Application.status to color
  draft     -> red
  submitted -> gray
  passed    -> blue
  else      -> gray
```
- else が無いとエラー。ただし、宣言された状態を全部書いた match は else を省略できる。
- 宣言に無い状態を左側に書いたらエラー（打ち間違いを止める）。
- 左側は `|` でまとめられる: `saturday | sunday -> weekend`。
- match の中に match は書けない（入れ子）。

### rule ★ — きっかけ → やること
```
rule Remind
  why   締切を落とさないため
  when  every day at 21:00
  do    notify owner each of DueSoon
  example
    given   Application
      company   "Osaka Gas"
      deadline  "9/24 23:59"
      status    draft
    at      "9/21 21:00"
    expect  notify "Osaka Gas"
```
- rule は `why`（任意）/ `when` / `where`（任意）/ `do` / `example` で書く。

**when — きっかけ**
- **when は出来事だけ。** 状態は where に書く（`when deadline within 3 days` は禁止）。
- when に書ける出来事（閉じたリスト）:
  - 時間: `every day at 21:00` / `every monday at 9:00` / `at 9/24 23:00`
  - 人: `user says "..."` / `user taps X on 画面か thing`
  - 書き方は決めたが、まだ実行エンジンが起こさないもの（check で E07）: `user holds X` / `user swipes X left` / `user drags X to Y` / `user types in X` / `user opens Scene` / `user leaves Scene`。board の列の移動は `〇〇 moves to 状態` として起きる。
  - 一覧の元は `ponte/forms.py`。`python -m ponte guide --rules` で表にして出せる。
  - データ: `〇〇 is created` / `〇〇 moves to 状態` / `〇〇 is removed`
  - 外: `Gmail gives new message`（connect の gives）
- `{...}` で取り出した値は変数になる。対象の箱は必ず絞る:
  `when user says "submitted {company}"` → `do move Application where company is {company} to submitted`
- 画面で押された1件は `this` で指す。

**where — 起きる条件**
- rule の where は、押された1件（this）の条件。合わない時、その rule は**静かに起きない**（失敗の通知も出ない）。画面のボタンも押せなくなる。
```
rule Borrow
  when  user taps borrow-button on Item
  where status is free
  do    create Loan
          item  this
          due   7 days from now
```

**do — やること**
- **do は1つだけ。** 2つやりたい時は rule を分けて、relate の `then` でつなぐ。
- 書ける形は次の表だけ。ほかの書き方は check でエラー（E31）。

| 書き方 | すること |
|---|---|
| `notify me "..."` | きっかけの人に通知 |
| `notify owner each of DueSoon` | 一覧のそれぞれの箱の owner が指す人に通知 |
| `move this to submitted` | 押された1件の状態を動かす |
| `move item of this to lent` | this の item 項目が指す箱を動かす |
| `move Application where company is {company} to submitted` | 絞った箱を動かす |
| `remove this` | 押された1件を消す（7.3） |
| `go Detail` / `go Detail with this` | 画面を移る |
| `create Loan`（下に字下げして「項目 値」） | 箱を作る |
| `set yen to result` | 項目を書き換える（状態は set でなく move） |
| `FindYen` / `FindYen with memo` | action を呼ぶ。with で入力を this の項目から渡す |
| connect の does（`Gmail send mail` など） | 外に頼む |

- **通知は宛先を書く。** 宛先は `me` か、項目の名前（`notify borrower "..."`）。通知の `{item}` は this の項目か when の `{…}`。別の箱を指す項目なら、指している箱の名前になる。

**値の書き方**（create の「項目 値」と set の値）

| 値 | 意味 |
|---|---|
| `this` | 押された1件 |
| `me` | 今使っている人 |
| `"文字"` | そのままの値 |
| `7 days from now` | 今から（minutes / hours / days / weeks）。年まで入れて保存する。推測しない |
| `{名前}` | when で取り出した値 |
| `項目 of this` | this の項目の値 |
| `result` | 直前の action の答え（set だけ。std の例は 9.5） |

**そのほか**
- ルール同士の関係は relate に書く。
- flow の状態ごとにルールを書いていて抜けがある → 「passed のときは？」と警告。

### relate — ルール同士の関係
```
relate
  ReadMail     then    FileMail
  ManualAdd    then no FileMail
  CheckSpam    before  FileMail
  NotifyFailed >       Remind
  LineNotify   else    MailNotify
```
全部の行が「左が先、右が後」。

| 書き方 | 意味 |
|---|---|
| `A then B` | Aが終わったらBが動く |
| `A then no B` | Aをやったら、この後Bは動かない。Bがもう済んでいても取り消さない |
| `A before B` | Bが動く時、Aは済んでいる。Aが終わってもBは勝手に動かない |
| `A > B` | 同時に当てはまったらAが勝つ |
| `A else B` | Aが失敗したらBをやる |

- `A then B` の途中で落ちても、言語が裏で「この箱で A は済んだ」を記録するので続きからやれる。
- action にも else があり、relate でも同じ action に else がある → エラー（逃げ道は1つだけ）。

### action ★ — 中身が空の箱（契約だけ書く）
```
action ExtractDeadline
  in      mail text
  out     found monthday | missing
  example "10/15(木)12:00まで"            -> found 10/15 12:00
  example "【締切9/24 23:59】"            -> found 9/24 23:59
  example "来週中にご提出ください"        -> missing
  example "9/24 23:59 または 9/30 23:59"  -> missing
  never   guess the year
  else    ask user
  by      ai
  how
    limit 5 seconds
```
- 旧 input / output は in / out。
- example 最低2つ必須。中身は例を全部通らないと採用されない。
- else 必須: 自信が無い時の逃げ道（`ask user` / `use default ...` / `skip`）。
- **契約の矛盾はエラー。** example の答えが out の型に合わない、never と out の型がぶつかる（`never guess the year` なのに out が年の要る date）など。
- **機械が確かめる never。** 次の never は、中身ができた時に機械が大量の入力で確かめる。それ以外の never は、今は機械では確かめられない（AIへの指示にはなる）。

| never | 確かめ方 |
|---|---|
| `guess the year` | 例の入力と、年の無い入力をいくつか流して、答えに年（4桁の数）が出ないか |
| `depend on width` | 例の入力を全角にして流し、半角の時と同じ答えになるか |
| `return empty` | 例の入力とおかしな入力を流して、値が空の答えを返さないか |
| `fail` | おかしな入力（空・長すぎる・絵文字・ありえない日付など）でも止まらないか |
- 失敗や「見つからない」も out の状態で表す（`found ... | missing`）。
**by ― 誰が中身を埋めるか ★**

| 書き方 | いつ | 中身 |
|---|---|---|
| `by ai`（標準） | ビルドの時に1回 | AIが do を書いて固定する。人も読めて直せる |
| `ask ai` | 実行の度に毎回 | AIに聞く。do は無い。how に時間かお金の上限が必須 |
| `by code "extract.ponte"` | — | 自分で書いた do |
| `by Gmail` | 実行の度に | connect 先がやる |

誰が埋めても、同じ example・never・else で検証される。

**do ― action の中身**
```
  do
    text  = normalize mail
    hits  = find all Deadline in text
    kind[one | none | many] = match count of hits
                                1    -> one
                                0    -> none
                                else -> many
    found = match kind
              one  -> found monthday of first of hits
              none -> missing
              many -> missing
```
- 書けるのは `名前 = 式` と、名前を付けた match だけ。
- **答えは「他のどの行からも使われていない行」。** ちょうど1つでなければエラー。答えの行に `[...]` は要らない（形は out に書いてある）。書いた場合は `answer[found monthday | missing]` のように out の形と同じにする。
- 一時的な状態は `名前[a | b] = match ...` で宣言して使う。
- 書き換え・ループ・再帰・true/false は無い。だから必ず止まる。
- 順番は名前の依存関係で決まる。上から順に実行されるわけではない。
- 使える道具は 10章。

**shape ― 文字の形（正規表現の代わり）**
```
shape Deadline
  month  digits 1..2
  "/"
  day    digits 1..2
  maybe  "(" any 1 ")"
  maybe  space
  hour   digits 1..2
  ":"
  minute digits 2
```

### how ★ — どうやるか（任意）
- rule と action の中にだけ書ける。
- 書かなければAIが決める。書いたらAIはその通りにしか作れない。
- 例: `check every 10 minutes` / `limit 5 seconds` / `limit 1 yen` / `on failure retry 3 times` / `repeat ... until 〇〇 or 1 hour passed`
- until は回数か時間の上限必須。無いとエラー（無限ループ防止）。
- action の `limit N seconds` と `on failure retry N times` は、動かす時に守られる（時間を過ぎたら失敗、失敗したら決めた回数だけやり直す）。

### group — まとまり
```
group Mail
  rule ReadMail
    when  Gmail gives new message
    do    ExtractDeadline

  rule FileMail
    do    create Application

  relate
    ReadMail then FileMail
```
- 名前で括るだけ。継承は無い。外からは `Mail.ReadMail` で呼ぶ。
- group の中の字下げは入れ子と数えない。group の中に group は書けない。
- 別ファイルは `use "mail.ponte"` で取り込む。エラーは取り込んだ元のファイルと行で出る。

### tbd ★ — まだ決めてないこと（旧 unknown）
```
tbd
  timezone of deadline
  who can delete Application
```
- 残っているとビルドできない。AIは埋めずに質問してくる。
- `##` との違い: tbd は答えが無い。`##` は答えの案がもう書いてある。

### never ★ — やってはいけないこと
- action の中にも、ファイル全体にも書ける。
- 生成されたコードのガード＋テストになる。証明できる違反はビルド前にエラー。
- action の never は、自動で作った大量の入力で検証する（例: 年の無い入力を何百個も作り、全部 missing か else になるか確かめる）。

## 6. 画面

「何を見せるか」を scene・look・part・input に、「どう見せるか」を style に書く。書かなかった見た目はAIが決める。

### scene — 場面
```
scene Home
  menu[open | closed] = closed
  top     Header
  main    match count of DueSoon
            0    -> EmptyNote
            else -> DueSoon as cards
  side    Application as list
  bottom  button add
  over    match menu
            open   -> Menu
            closed -> nothing
```
- 置き場所は `top` / `main` / `side` / `bottom` / `over`（上に重ねる）。細かく並べる時は `row` / `column` / `grid 3`。
- 出し分けは match。`nothing` は何も出さない。
- 画面だけの状態は `名前[a | b] = 最初の値`。

### 画面の移動
```
flow scene
  Home -> Detail -> Edit
  Home -> AddApplication

rule OpenDetail
  when  user taps card on DueSoon
  do    go Detail with this
```
- flow scene の矢印の通りにしか移動できない。矢印に無い移動はエラー。

### look — 見せ方
```
look DueSoon as cards
  title   company
  sub     DeadlineBadge of deadline
  mark    color of status
  button  submitted-button named 提出した

look Header
  button menu-button   named メニュー  toggle menu
  button close-button  named 閉じる    set menu closed
```
- 見せ方の種類: cards / list / table / detail / input / calendar / board / chart / tabs / dialog / sheet / toast / map / media
- board は flow から状態ごとの列が自動でできる。カードを動かすと move の出来事が起きる。
- **chart は状態ごとの件数の棒。** `group by 項目` で分け方を、`sum 項目` で高さを合計に変えられる（数の項目だけ。例: 家計メモの「費目ごとの合計」）。
  ```
  look ByKind as chart
    group  by kind
    sum    yen
  ```
- **画像。** thing の項目を `photo image` にして input に書くと、画像を選べる（png / jpg / gif / webp、5MB まで。中身の頭で種類を確かめる）。一覧では look に `image photo about name` と書くと、写真が出る（`about` は読み上げの説明。公開する時は必須）。画像は、その箱を who で見られる人にだけ出る。
- input に状態の項目を書くと、選ぶ形になる。ただし flow のある状態は選べない（ボタンの rule で move する）。
- **画面だけの状態は look の中で `toggle 状態` / `set 状態 値` と書ける。** rule は要らない。データ（thing の項目）は rule の move でしか変えられない。

### part — 自分で作る部品
```
part DeadlineBadge
  in    deadline monthday
  do
    left = days until deadline
    urgency[today | soon | later] = match left
      0    -> today
      1..3 -> soon
      else -> later
  show  text "あと{left}日"
  mark  urgency
```
- 名前を付けて、どこでも使い回せる。
- part の中で part を使うのは可。part の中で part を定義するのは不可。
- 言語の見せ方で描けない絵は `part 名前 by ai`。example で「このデータの時にこうなっているか」を検証する。見た目の良し悪しまでは機械で検証できない。

### input — 入力
```
input AddApplication
  company   required
  deadline  required, from now
  memo
  resume    file, pdf only, max 5 MB
```
- 送ったら `Application is created` の出来事が起きる。
- 入力のチェックは項目の隣に書く。満たさない時の表示は言語が出す。`required`（必須）と `from now`（今より後）は、画面とサーバーの両方で守られる。

### style — 見た目
```
style theme
  color main  #2F6FEB
  space s     8

style DueSoon
  card     round 12, shadow soft, pad 16
  title    size 18, bold
  mark     dot left
  gap      16
  enter    fade 200ms
  reorder  slide 150ms

style Home on phone
  main  column
style Home on wide
  main  grid 3
```
- 色・大きさ・余白・角丸・影・フォント・動き・並べ方まで書ける。
- 画面の大きさは `on phone | tablet | wide`。
- 書かなかった所はAIが決める。

### words — 画面の文字と多言語
```
words ja
  add  追加
words en
  add  Add
```
- 片方の言語だけ訳が無い → エラー。
- **1つの言語だけのアプリなら words は要らない。** `named "借りる"` / `empty "まだありません"` のように、画面の文字を `"文字"` でそのまま書ける。
- **words がある spec では、画面の文字は words の名前で書く。** ボタンの名前・見出し・空の時の文・確認の文・部品の文・部品が計算する文が対象。words に無ければエラー（E25）。日本語は words ja に1回だけ書く。
```
look DueSoon as cards
  heading  due-heading
  button   submitted-button named submit icon send

words ja
  due-heading  3日以内に締切
  submit       提出した
words en
  due-heading  Due within 3 days
  submit       Mark submitted
```
- 言語が出す文字（`search` `save` `cancel` `none`）も words で訳せる。
- words が無い spec は、画面の文字をそのまま書ける。
### 読み上げ対応
- 名前の無いボタン（`named` が無い）、説明の無い画像（`about` が無い）は、試作の間は注意、公開する時はエラー。

### 画面の小さな部品 ★
画面を作り込む時に足した小さな部品。どれも1つの仕事だけ。

| 書き方 | 意味 |
|---|---|
| `main  tabs tab` | 画面の状態 `tab[...]` を切り替えるタブを出す |
| `main  this as detail` | 前の画面で押された1件を詳しく見せる |
| `look Application as detail` | thing の名前の look は、詳しく見せる時の見せ方 |
| `empty "..."`（look の中） | 1件も無い時に出す文 |
| part の中の `do` | 部品の中で値を計算する。action の中身と同じく `do` の下に `名前 = 式` と `名前[a \| b] = match ...` |
| `days until X` | 今日から X までの日数（今日なら 0、過ぎていればマイナス） |
| match の左の `1..3` / `..-1` / `4..` | 数の範囲（両端を含む） |
| `match 部品名.状態 to color` | 部品の状態ごとの色 |
| ボタンの行の `tone main \| quiet \| good \| danger` | ボタンの強さと色（`button failed-button named 不合格 tone danger`）。書かなければ一覧の最初のボタンと画面の下のボタンだけ強い |
| `#4F46E5` | `#` のすぐ後ろに16進の色が続く時は、コメントではなく色の値 |
| `user taps X on 箱の名前` | list の名前でなく thing の名前で書けば、どの一覧・ボード・詳しくから押しても動く |
| `button 名前 named 文字 icon 名前` | ボタンにアイコン。アイコンは組み込みの24個だけ（無い名前はエラー） |
| `button 名前 named 文字 confirm "文"` | 押す前に確かめる。やめれば何も起きない |
| `named "空白を含む 名前"` | 名前は1語。空白を含むなら引用符。ボタンの行に知らない語があればエラー |
| `match Application.status to icon` / `match tab to icon` | 状態ごと・タブごとのアイコン（色の match とは別に持てる） |
| `lead company`（look の中） | 頭文字の丸 |
| `heading "..."`（look の中） | 見出しと件数 |
| `search company, memo`（look の中） | 一覧の検索 |
| `group by status`（look の中） | 状態ごとにまとめる |
| `take 20`（look の中） | 最初に見せる件数。残りは「もっと見る」 |
| `empty "..." button add named 追加`（look の中） | 1件も無い時の文と、次にやることのボタン |
| `top  notices` | お知らせのベル（未読の数と一覧） |
| `go EditApplication with this` | input を with this で開くと、その1件の編集。状態の項目は書き換えられない（move だけ） |
| words の `"引用符の鍵"  訳` | spec にそのまま書いた日本語も訳せる |

言語が画面を守るもの:
- **flow で動けないボタンは、自動で押せなくなる。** rule が `move this to X` で、いまの状態から X へ動けなければ、そのボタンは薄くなって押せない。
- **board でカードを動かすと move が起きる。** flow に無い流れは「『下書き』から『通過』へは動かせません」と断られる。
- 画面の下（bottom）のボタンだけが目立つ色。上や一覧のボタンは控えめ（最初のボタンだけ強い）。
- look の title / lead / search / group by に無い項目名、無いアイコン名、読めないボタンの行はエラー（E28）。

### 件数と合計
`main  stats Mine, sum yen of Mine` … 一覧の件数と、項目の合計を並べる。見えるものだけ数える。見出しは words の名前（合計は「金額の合計」）。数は3けたごとに区切る。sum は数の項目だけ（E32）。

### リアルタイム
- 何も書かなくても画面は常に最新。箱が変わったら、それを見せている画面が自動で変わる。

## 7. データと人

### 7.1 who — 誰が何をできるか
```
who
  user   can see    Application where owner is me
  user   can change Application where owner is me
  admin  can do     everything
  nobody can remove Application
```
- 書いてないことは誰もできない。
- who が1行も無い thing → エラー。
- rule も who に従う。user says や user taps で動く rule は、その人ができることしかできない。
- ログインの方法は connect に任せる。
- **役割。** `user` 以外の役割（admin など）は、`thing User` の `role[member | admin]` に書く。その人の role の値が役割になる。書いてない役割を who に使うとエラー（E28）。
  - 役割を変えるのも、ふつうの状態と同じ（flow User.role・rule・who で守る）。
  - **最初の1人だけ**は仕様から決められないので、`ponte role spec.ponte taro admin` で決める。2人目からは画面で。
  - `where it is not me` で「自分には使えない」を書ける（自分を管理者から外せない＝管理者が0人にならない）。
- 動詞: `see` / `create` / `move`（状態を動かすだけ）/ `change`（作る・動かす・書き換える）/ `remove`。
- 入力を開くボタンは、その thing を作れる人にだけ出る。

### 7.2 保存
- 保存は言語が持つ。thing を書けばデータは残る。何のDBかは書かない。

### 7.3 消した時の扱い
- 他の箱を指す項目には `gone[...]` を必ず書く。無ければエラー。
- 消すのは rule の `do remove this`。who の `can remove` が要る。消すと `〇〇 is removed` の出来事が起きる。

| 書き方 | 意味 |
|---|---|
| `gone[remove too]` | 一緒に消す |
| `gone[leave empty]` | 空にする |
| `gone[block]` | 指されている間は消せない |

### 7.4 thing を変えた時
```
change Application to v2
  add     memo text = ""
  rename  company to corp
  remove  owner
  remove  state passed -> failed
```
- thing の形が前回のビルドと違うのに change が無い → エラー。
- 動かす時、保存してある古いデータは change の通りに今の形へ移る（足した項目の初期値、名前の変更、消した項目、消した状態の移し先）。
- 足した項目の初期値が無い → エラー。
- 状態を消す時は、その状態だった箱の移し先が必須。

## 8. 外とつながる（connect）
```
connect Gmail
  gives   new message  Message
  does    send mail    to text, body text -> sent | failed
  needs   key GMAIL_TOKEN
  limit   100 per hour
```
- `gives`: 向こうから届く出来事。`when Gmail gives new message`。
- `does`: こちらから頼めること。結果は必ず状態。
- `needs`: 秘密の値。値そのものは仕様に書かず、実行する時に渡す。
- `limit`: 回数の上限。
- does の失敗の逃げ道（relate の else か、結果を match して書く）が無い → エラー。
- **依存ゼロ:** 言語の中は依存ゼロ。外との境界は connect に宣言した口だけ。

## 9. テスト（example）

```
rule MarkSubmitted
  when  user says "submitted {company}"
  do    move Application where company is {company} to submitted
  example
    given   Application
      company  "Osaka Gas"
      status   draft
    given   Application
      company  "Other"
      status   draft
    says    "submitted Osaka Gas"
    expect  Application is submitted
      company  "Osaka Gas"
    expect  Application is draft
      company  "Other"
```
- 3段: `given`（前の状態）→ 出来事 → `expect`（結果）。
- **箱の中身は字下げして1行1つで書く。** `given Application` の下に `company "Osaka Gas"` のように並べる。カッコと `,` は使わない。
- given で別の thing を指す項目は、その箱の名前で書ける（`item "カメラ"`）。
- 前の状態: `given 箱`（下に中身）
- 出来事: `at "..."` / `says "..."` / `taps X on 箱の名前`（下に中身）/ `taps X on 画面の名前` / `gets Gmail new message "..."` / `adds 箱`（下に中身。人が作ったことにする。`〇〇 is created` の出来事も起きる）
- 結果: `expect notify "..."` / `expect X is 状態` / `expect 箱`（下に中身。その中身の箱があるか）/ `expect no Loan` / `expect 2 Loan`（数）/ `expect scene Detail` / `expect Home shows 2 cards`（無い scene に shows を書いたら失敗）/ `expect nothing`

**穴さがし。** `ponte test` は、example が全部通った上で「どの example も確かめていない所」を出す（`--strict` で失敗にする）。
- when がある rule なのに、example が無く、どの example の中でも動いていない
- flow の矢印（`a -> b`）を、どの example も通っていない
- action の out の答えの形（found / missing など）を出す example が無い

## 9.5 標準ライブラリ

`use std/名前` で、言語についてくる .ponte を読む。中身もこの言語で書いてあり、全部に example と never が付いている（`ponte test` で一緒に流れる）。

| 読み方 | action | 答え |
|---|---|---|
| `use std/date` | FindMonthDay | `found monthday`（年は推測しない）/ missing |
| `use std/date` | FindDate | `found date`（年が書いてある日付だけ。13月など無い日付は missing）/ missing |
| `use std/money` | FindYen | `found number`（¥ が前でも 円 が後ろでも。全角も）/ missing |
| `use std/contact` | FindEmail / FindPhone / FindPostal | `found text` / missing（郵便番号は 150-0001 の形。電話番号の途中には当たらない） |

- どれも「2つ以上あったら決めない（missing）」。else は skip。
- rule から使う: `do FindYen with memo`（入力は押された1件の memo）→ `relate ReadYen then SaveYen` → `do set yen to result`。
- 答えが出なかった時（missing / skip）、result を使う rule は静かに起きない。

## 11. 実行モデル ★
- 箱＝アクター。thing 1件ごとに独立。Erlang / Go の goroutine＋channel と同じ思想。
- ルールは全部独立。並列を書かなくても並列。
- 同じ箱への書き換えは届いた順に1つずつ。矛盾は flow の `>` で決める。
- ルール同士の順番と強さは relate で決める。
- 画面は箱の変化を受けて自動で変わる。
- **実行するもの:** 自前の実行エンジンで spec を直接動かす。その後 WebAssembly に直接変換する。Go など他の言語やライブラリには依存しない。

## v0.3 整理メモ

**動かした所**
- rule の追補（where・create の中身・項目 of this・set・with・E31）→ rule の節を when / where / do / 値 に分け、do の形を1つの表、値を1つの表にした。
- 「画面のための追補」→ 6章「画面の小さな部品」。
- 「件数と合計」→ 6章のまま、見出しから追補を外した。
- 役割 → 7.1 の who の中に並べた。
- 穴さがし・example の書き方 → 9章の本文。出来事と結果の一覧に adds / expect 箱 / expect no / expect 2 を入れた。
- 標準ライブラリ → 9.5（追補の見出しを外した）。
- 10章の追補（名前 of X、+ の強さ、状態名と行名、word with）→ 10章の箇条書き。
- 13章 → v0.1 / v0.2 の区切りを外して 1〜32 の番号の並びに。32 の中身は下の箇条書きへ。警告を別に書いた。
- 16章 → 16.1「v0.2 → v0.3 で入ったもの」と 16.2「v0.1 → v0.2 の主な変更」。
- 「（v0.2）」の印は全部外した。

**ぶつかっていた所・コードに合わせた所**
- 通知の宛先: v0.2 本文は `notify me` / `notify owner each of 一覧` の2つだけ。コード（DO_FORMS）は `notify 項目 "..."`（例 `notify borrower "..."`）も通す。コードに合わせた。
- go: 本文は `go Detail with this` だけ。コードは `go 画面` も通す（kakeibo の `go AddExpense`）。両方書いた。
- 期間の値: 追補は `7 days from now` だけ。コードは minutes / hours / days / weeks を通す。コードに合わせた。
- 値の書き方: コードは表の値のほかに、ただの語や数（状態の名前、数など）も値として通す。表には書いていない（決まりとしては変えていない）。
- 役割のエラー: who の役割は、`user`・`nobody`・User の role の状態のどれか。コード（check_roles）どおり E28。
- E28 の対象: コードは create の無い項目、stats の書き方、who の役割も E28 で出す。13章の 28 に足した。stats の sum が数でない時は E32。
- E25: 本文（6章 words）は「画面の文字が words に無ければエラー（25）」。13章の 25 は訳が無いことだけだったので、両方を 25 に書いた。
- 13章の 26 は v0.2 で「公開する時だけエラー、試作中は警告」。6章「読み上げ対応」と同じ意味なのでそのまま。
- 9 は v0.2 でも警告。番号は残し、警告の欄にも書いた。
