HOW

しくみ — ponte/ の中

依存は Python 3.11 の標準機能だけ。

 .ponte ──parser──▶ 木（見出しと節） ──checker──▶ エラー32種・警告
                        │
                        ├──examples──▶ example と never を流す → 穴さがし
                        │
                        ├──fill──▶ AIに action の中身を書かせる ⇄ 確かめて問題を返す
                        │
                        └──runtime──▶ 実行エンジン ──server + page.html──▶ ブラウザの画面

ファイル

ファイルすること
parser.py行の字下げで木にする。行頭が見出し（thing / rule …）、字下げが節。# はコメント、## は止めるコメント（#4F46E5 のような色は値）。use で別ファイル・use std/… で標準ライブラリを読む
checker.pyエラーを探す。1つの決まり＝1つの関数（ALL_CHECKS）。E32 の型は rule ごとに this が何の thing かを推論して確かめる
forms.pyrule の when・do・値の書き方の一覧。チェッカーも説明もここから作る
body.pyaction の中身（do と shape）を動かす。TOOLS が道具の一覧（説明・エラーの一言・仕様書の表もここから）
examples.pyexample を実行エンジンで流す。holes() が穴さがし
runtime.py実行エンジン。箱（データ1件）ごとに鍵1つ、箱をまたぐと並列。flow・who・relate・通知・取り消し。保存は JSONL の追記（読み直して同じ中身に戻る）
server.py標準の http.server。画面の組み立て（scene → 部品の JSON）、入力の検査、リアルタイム（SSE）、--reload の入れ替え
auth.pyponte run --login のログイン。合言葉は hashlib.scrypt、鍵は HttpOnly の cookie（メモリにだけ持つ）
errors.pyエラーの辞書（なぜ止めるか・どう直すか）。ponte explain・check --json・仕様書 13章・ホームページはここから
page.html画面そのもの（素の HTML / CSS / JavaScript。ライブラリ無し）。ダークモード・スマホ・英語
fill.pyAIに中身を書かせる。urllib で API を呼ぶ（SDK 無し）。書いた中身は example と never で確かめ、ダメなら問題を返して書き直させる
guide.pyAIへの書き方の説明を、TOOLS・forms.py・std から作る（ponte guide）
fmt.py整形。見た目の幅でそろえる。意味が変わるなら書かない
build.py1つの .pyz にまとめる（std も入る）
values.py日時・期間の読み書き
icons.py画面のアイコン
doc.pyponte doc。決めごとを1枚の HTML に
lsp.pyponte lsp。エディタ向けの言語サーバー（標準入出力の JSON-RPC。check・errors・TOOLS を使う）
cli.pyコマンド
std/標準ライブラリ。中身もこの言語で、example 付き

大事な決まり（実装の側）

  • 一覧は1か所だけ。 道具（body.TOOLS）、rule の書き方（forms.py）、エラー（errors.ERRORS）、機械で確かめる never（fill.MACHINE_NEVERS）。説明・エラー・仕様書の表・ホームページはそこから作り、ずれたらテストが落ちる（tests/test_guide.py・test_errors.py・test_docs.py）。
  • 年は推測しない。 年の無い日付は年の無いまま持つ。「今より前」の締切は画面で聞き返す。
  • 書いてないことは誰もできない。 who に無い操作は、画面のボタンも出さないか押せなくする。
  • 例が通っても、確かめていない所は言う。 ponte test の穴さがし。

テスト

python -m pytest（320件ほど、10秒ほど）。

ファイル確かめること
test_checker.py、cases/エラーごとに「壊した仕様」と「直した仕様」の組（make_cases.py で作る）
test_types.py型（E32）。わざと壊した12通りを止める
test_engine_fuzz.pyエンジンをでたらめに40通り×60操作。flow・who・通知先・読み直しの約束
test_guide.py道具の例が全部動く・仕様書の表と実装がずれていない
test_docs.py入門の出力が本物・見本のアプリが全部通る・ホームページが docs と実装から作ったものと同じ
test_errors.pycheck が出すエラーが全部辞書にある・explain・check --json
test_auth.pyログイン（本物のサーバーを立てて、cookie・合言葉・登録・間違いの続き・外に開く時の止め）
test_std.py標準ライブラリ
test_runtime.py、test_spec_gaps.py、test_ui_language.py実行エンジン・サーバー・画面
test_lend.py役割・取り消し・2つの thing
test_fill.py、test_experiment_v2.pyAIの穴埋めのループ・実験の採点
