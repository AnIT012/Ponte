プログラムのいちばん上の層に書く言語

何を作るかだけ書く。あとは言語が守る。

Ponte で書くのは、データの形、誰が何をできるか、何が起きたら何をするかだけです。書いたことは必ず守られる約束になり、決めていないことが残っていれば、動かす前にエラーで止まります。Python や Java は、その下で動く層になります。

ブラウザで試す入門を読む

覚える言葉は少なく、自分だけで書いても完結します。AI と作るときは、同じ仕様が AI への指示になり、AI が守る約束になります。

todo.ponte
thing Task
  title   text
  due     monthday
  owner   User  gone[remove too]
  status  [todo | done]

thing User
  name  text

flow Task.status
  todo -> done -> todo

who
  user  can see     Task  where owner is me
  user  can change  Task  where owner is me
  user  can see     User  where it is me

rule Finish
  when   user taps done-button on Task
  where  status is todo
  do     move this to done
↓ ponte run todo.ponte
Ponte何を作るか。決めたこと、してはいけないこと、まだ決めていないこと
Pythonいまはこの上で動きます
JavaScript / TypeScript・Go・Java下の層として選べるように準備しています
機械アセンブリ、CPU

決めるのは人。守るのは言語。

決め忘れ

決めていないことは、動かす前に止まる

まだ決めていないことは tbd に書いておけます。1つでも残っていれば ponte check が通らず、動きません。曖昧なまま先に進むことはありません。

thing Order
  item    text
  status  [new | paid | shipped]

flow Order.status
  new -> paid -> shipped

who
  user  can see     Order
  user  can create  Order

tbd  発送した後でも、キャンセルできる？
$ ponte check order.ponte
Stopped: 1 error(s)
  order.ponte:12  E05  tbd remains: "発送した後でも、キャンセルできる？". Decide it before running
  (how to fix: ponte explain E05)

権限

書いていない権限は、誰にもない

誰が何を見られるか、変えられるかは who に書きます。書いていない操作は誰にもできません。書き忘れは「誰も使えない」になるので、エラーとしてすぐに見つかります。

thing Task
  title   text
  status  [todo | done]

flow Task.status
  todo -> done
$ ponte check nowho.ponte
Stopped: 1 error(s)
  nowho.ponte:1  E19  thing Task: no who lines saying who can do what. Nobody can do anything that is not written
  (how to fix: ponte explain E19)

約束

中身は、約束を先に書いてから

計算や判定の中身は action に書きます。先に答えの例と、してはいけないことを書き、中身はその下の do に書きます。中身は自分で書いても、by ai で AI に任せてもかまいません。どちらでも同じ約束で確かめます。

action Grade
  in       score number
  out      pass | fail
  example  80 -> pass
  example  59 -> fail
  never    fail
  else     skip
  do
    answer = match score
      60.. -> pass
      else -> fail
$ ponte test grade.ponte
  pass  action Grade (L4)
  pass  action Grade (L5)
  pass  action Grade (L6)
3 examples, 3 passed

テスト

例がそのままテストになる

ルールの下に書いた example が、そのままテストになります。ponte test は例が通るかを確かめたうえで、まだどの例でも確かめていない部分を一覧にします。example は書かなくても動きます。

$ ponte test spec/hub_ready.ponte
  pass  rule Remind (L57)
  pass  rule MarkSubmitted (L68)
2 examples, 2 passed
Untested parts (not covered by any example: 2)
  spec/hub_ready.ponte:12  flow Application.status: no example covers submitted -> passed
  spec/hub_ready.ponte:12  flow Application.status: no example covers submitted -> failed

下の層

渡した値が、下で本当に効いたかを確かめる

下の層（Python や PyTorch）に任せた部分でも、約束は届きます。with で渡した値を、下の層に「実際に使った値」として報告させ、confirm で照合します。学習率を渡したつもりが既定値のまま、のような事故は、学習を待たずにその場で止まります。require（結果の条件）と suspect（良すぎる数字など、おかしいときに止める条件）も書けます。

job Train
  run      python3 train_demo.py
  with     learning_rate 1.25e-4, batch_size 32
  confirm  learning_rate, batch_size
  require  classes is 3
  suspect  test_accuracy above 75
$ ponte job job.ponte Train
job Train: running
  confirm learning_rate: declared 1.25e-4, but 0.001 was actually used (stopped the run)
job Train: contract broken (1 problem(s))

ほかの作り方との違い

Python などで直接書くAI に日本語で頼むPonte
覚えること言語と、たくさんの道具ほとんどない少ない言葉だけ
決めていないこと書く人が気づかずに埋めるAI が推測して埋めるエラーで止まり、人が決める
権限自分で作る。漏れやすい書き忘れると誰でも操作できる書いた操作しかできない
確かめ方テストを別に書く動かして画面を目で見る例がテストになり、確かめていない部分も一覧になる
読める人コードが読める人だけ誰でも読めるが、曖昧誰でも読めて、曖昧さがない

1つのファイルから動くもの

画面やサーバーのコードは書きません。仕様を書けば、次のものがそろった状態で動きます。

  • ログインと登録
  • 一覧・ボード・カレンダー
  • 入力フォームと確認
  • 通知と定期実行
  • リアルタイム更新
  • 画像のアップロード
  • スマートフォン表示
  • ダークモード
  • 日本語と英語

書き方を6つの見本で見る

# データの形：やることと、その持ち主
thing Task
  title   text
  due     monthday
  owner   User  gone[remove too]
  status  [todo | done]

thing User
  name  text

データの形を書く

thing には、アプリが持つデータの形を書きます。項目の名前と型を並べておけば、保存や読み書きは Ponte が引き受けます。状態は [todo | done] のように、取りうる値をすべて書いておきます。

# 状態の流れと、誰が何をできるか
flow Task.status
  todo -> done -> todo

who
  user  can see     Task  where owner is me
  user  can change  Task  where owner is me
  user  can see     User  where it is me

状態の流れと権限

flow には状態がどう移れるかを、who には誰が何をしてよいかを書きます。who に書いていない操作は誰にもできません。そのため、権限の書き忘れはエラーとして見つかります。

# 毎朝8時に、明日までのやることを知らせる
list Soon
  of     Task
  where  status is todo
  where  due within 1 days

rule Remind
  why   明日までのものを忘れない
  when  every day at 8:00
  do    notify owner each of Soon

きっかけとすること

rule には、きっかけとそのときにすることを一組で書きます。when に書けるのは時刻やボタンのような出来事だけで、「明日まで」のような条件は list の where で絞ります。

# ボタンを押したら終わりにする。例を書くとテストになる
rule Finish
  when   user taps done-button on Task
  where  status is todo
  do     move this to done
  example
    given   Task
      title   "牛乳を買う"
      status  todo
    taps    done-button on Task
      title   "牛乳を買う"
    expect  Task is done
      title   "牛乳を買う"

例がテストになる

rule の下に example を書くと、それがテストになります。ponte test は例が通るかを確かめるだけでなく、まだ例で確かめていないルールや状態の変化も一覧で示します。

# AIに任せる処理には、例と禁止事項を先に書く
action FindDeadline
  in       mail text
  out      found monthday | missing
  example  "10/15まで"     -> found 10/15
  example  "来週中に提出"  -> missing
  never    guess the year
  never    fail
  else     ask user
  by       ai

AI に任せる部分には約束を書く

処理の中身を AI に書いてもらうときは、action に入力と答えの例、してはいけないことを先に書きます。AI が書いた中身はこの約束に照らして機械で確かめ、守れていなければ書き直させます。

# まだ決めていないことは tbd に書く。残っているうちは動かない
tbd
  締切を過ぎたやることは、一覧に残すか消すか

決めていないことは tbd に

まだ決めていないことは tbd に書いておけます。tbd が残っているあいだは ponte check が通りません。このため、決め忘れたまま動き出すことはありません。
