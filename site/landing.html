AI と一緒にアプリを作るための言語

仕様を書けば、そのままアプリになる。

Ponte で書くのは「どう作るか」ではなく「何を作るか」です。データの形、誰が何をできるか、ボタンを押したら何が起きるかを書くと、ログイン付きの Web アプリとして動きます。決めていないことが残っていれば、動かす前にエラーで止まります。

ブラウザで試す入門を読む

Python 3.11 だけで動きます。ほかに入れるものはありません。

todo.ponte
thing Task
  title   text
  due     monthday
  owner   User  gone[remove too]
  status  [todo | done]

thing User
  name  text

flow Task.status
  todo -> done -> todo

who
  user  can see     Task  where owner is me
  user  can change  Task  where owner is me
  user  can see     User  where it is me

rule Finish
  when   user taps done-button on Task
  where  status is todo
  do     move this to done
↓ ponte run todo.ponte

人は決めて、AI が書いて、言語が守る。

1

決め忘れは、動かす前に止まる

AI にアプリを頼むと、決めていないことは AI が勝手に補って進みます。Ponte では、まだ決めていないことを tbd に書いておけます。1つでも残っていれば ponte check が通らず、アプリは動きません。

thing Order
  item    text
  status  [new | paid | shipped]

flow Order.status
  new -> paid -> shipped

who
  user  can see     Order
  user  can create  Order

tbd  発送した後でも、キャンセルできる？
$ ponte check order.ponte
止まります（1件）
  order.ponte:12  E05  tbd が残っています: 「発送した後でも、キャンセルできる？」— 決めてから渡してください
  （直し方: ponte explain E05）

2

書いていない権限は、誰にもない

誰が何を見られるか、変えられるかは who に書きます。書いていない操作は誰にもできません。書き忘れると「誰も使えないアプリ」になるので、エラーとしてすぐに見つかります。

thing Task
  title   text
  status  [todo | done]

flow Task.status
  todo -> done
$ ponte check nowho.ponte
止まります（1件）
  nowho.ponte:1  E19  thing Task: 誰が何をできるか（who）が1行もありません。書いてないことは誰もできません
  （直し方: ponte explain E19）

3

AI に任せる部分は、約束で囲む

文章から日付を拾うような処理は action にして、中身を AI に書かせます。先に答えの例と、してはいけないことを書いておきます。AI が書いた中身は、この約束に照らして機械が確かめます。

action FindMonthDay
  in       text text
  out      found monthday | missing
  example  "10/15(木)12:00まで"      -> found 10/15 12:00
  example  "来週中にご提出ください"  -> missing
  never    guess the year
  never    fail
  else     skip

4

例がそのままテストになる

ルールの下に書いた example が、そのままテストになります。ponte test は例が通るかを確かめたうえで、まだどの例でも確かめていない状態の変化を一覧にします。

$ ponte test spec/hub_ready.ponte
  通過  rule Remind（L57）
  通過  rule MarkSubmitted（L68）
example 2件中 2件通過
穴（example で確かめていない所 2件）
  spec/hub_ready.ponte:12  flow Application.status: submitted -> passed をどの example も通っていません
  spec/hub_ready.ponte:12  flow Application.status: submitted -> failed をどの example も通っていません

1つのファイルから動くもの

画面やサーバーのコードは書きません。仕様を書けば、次のものがそろったアプリとして動きます。

  • ログインと登録
  • 一覧・ボード・カレンダー
  • 入力フォームと確認
  • 通知と定期実行
  • リアルタイム更新
  • 画像のアップロード
  • スマートフォン表示
  • ダークモード
  • 日本語と英語

書き方を6つの見本で見る

# データの形：やることと、その持ち主
thing Task
  title   text
  due     monthday
  owner   User  gone[remove too]
  status  [todo | done]

thing User
  name  text

データの形を書く

thing には、アプリが持つデータの形を書きます。項目の名前と型を並べておけば、保存や読み書きは Ponte が引き受けます。状態は [todo | done] のように、取りうる値をすべて書いておきます。

# 状態の流れと、誰が何をできるか
flow Task.status
  todo -> done -> todo

who
  user  can see     Task  where owner is me
  user  can change  Task  where owner is me
  user  can see     User  where it is me

状態の流れと権限

flow には状態がどう移れるかを、who には誰が何をしてよいかを書きます。who に書いていない操作は誰にもできません。そのため、権限の書き忘れはエラーとして見つかります。

# 毎朝8時に、明日までのやることを知らせる
list Soon
  of     Task
  where  status is todo
  where  due within 1 days

rule Remind
  why   明日までのものを忘れない
  when  every day at 8:00
  do    notify owner each of Soon

きっかけとすること

rule には、きっかけとそのときにすることを一組で書きます。when に書けるのは時刻やボタンのような出来事だけで、「明日まで」のような条件は list の where で絞ります。

# ボタンを押したら終わりにする。例を書くとテストになる
rule Finish
  when   user taps done-button on Task
  where  status is todo
  do     move this to done
  example
    given   Task
      title   "牛乳を買う"
      status  todo
    taps    done-button on Task
      title   "牛乳を買う"
    expect  Task is done
      title   "牛乳を買う"

例がテストになる

rule の下に example を書くと、それがテストになります。ponte test は例が通るかを確かめるだけでなく、まだ例で確かめていないルールや状態の変化も一覧で示します。

# AIに任せる処理には、例と禁止事項を先に書く
action FindDeadline
  in       mail text
  out      found monthday | missing
  example  "10/15まで"     -> found 10/15
  example  "来週中に提出"  -> missing
  never    guess the year
  never    fail
  else     ask user
  by       ai

AI に任せる部分には約束を書く

処理の中身を AI に書いてもらうときは、action に入力と答えの例、してはいけないことを先に書きます。AI が書いた中身はこの約束に照らして機械で確かめ、守れていなければ書き直させます。

# まだ決めていないことは tbd に書く。残っているうちは動かない
tbd
  締切を過ぎたやることは、一覧に残すか消すか

決めていないことは tbd に

まだ決めていないことは tbd に書いておけます。tbd が残っているあいだは ponte check が通りません。このため、決め忘れたまま動き出すことはありません。
