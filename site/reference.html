道具とエラー

このページは Ponte の実装から作っています。道具の例は全部テストで動かしているので、ここに書いてあることはそのまま動きます。

コマンド

python -m ponte か、pip install -e . のあとは ponte だけで使えます。

コマンドすること
ponte check spec決めてないことを探す
--publish 公開する時の検査
--save-shape 通ったら thing の形を残す
--json 結果を JSON で出す（エディタや AI のループ向け）
ponte test specrule の example を全部流す
--strict 穴（example で確かめていない所）があれば失敗にする
--json 結果を JSON で出す
ponte fill specby ai の action の中身をAIに書かせる（example と never を通るまで）
--action この action だけ
--ai anthropic（ANTHROPIC_API_KEY が要る）か file:返事.md
--again もう中身があっても書き直す
ponte fmt spec…誰が書いても同じ見た目に整える
--check 書き換えず、整形が要るかだけ見る
ponte build specspec と中身と実行エンジンを1つの .pyz にまとめる
ponte run spec動かす（ブラウザで開く）
--data データを残すファイル（既定は <spec>.data.jsonl）
--login 名前と合言葉でログインする（登録は ponte user add）
--signup --login に加えて、画面から誰でも登録できる
--reload spec を書き直したら読み直して、画面も読み直す（作っている間に）
ponte user add|remove|list spec [name]ログインする人（例: user add spec/lend.ponte taro）
ponte new nameひな形から新しいアプリを作る
ponte guideAIに渡す書き方の説明を出す（実装から作る）
--spec 仕様書 10章の道具の表を書き直す
--rules rule の書き方（when / do / 値）を出す
ponte role spec name role最初の管理者を決める（例: role spec/lend.ponte taro admin）
--data データのファイル（既定は <spec>.data.jsonl）
ponte data export|import|compact spec [thing] [file]保存したデータを書き出す（export）・CSV から入れる（import）・詰める（compact）
--as import: 作った人（User を指す項目の既定）
--data データのファイル（既定は <spec>.data.jsonl）
--csv export を thing ごとの CSV にする
ponte doc spec決めごとを、コードを読まない人にも読める1枚の HTML に
--out 書き出す先（既定は <spec>.html）
ponte lspエディタ向けの言語サーバー（標準入出力。エラー・説明・補い）
ponte explain [code]エラーの意味と直し方（例: explain E32。無しなら一覧）

rule の書き方

rule は、きっかけ（when）とやること（do）の一組です。

when — きっかけ

書けるのは出来事だけです。状態（「期限が近い」など）は where か list で絞ります。

書き方意味
every day at 21:00 / every monday at 9:00毎日・毎週その時刻に
at 9/24 23:00その日時に1回
user says "submitted {company}"人が言った（{…} は変数になる）
user taps 名前 on 画面か thingボタンを押した（押された1件が this）
Loan is created箱ができた（this はその箱）
Loan moves to returned状態が動いた
Loan is removed箱が消えた
Gmail gives new messageconnect の gives が届いた（入力は届いた中身）

書き方は決まっていて、まだ起きないもの（check で止まります）: user holds 名前 / user swipes 名前 left / user drags 名前 to 名前 / user types in 名前 / user opens 画面 / user leaves 画面

do — やること

1つの rule でやることは1つだけです。2つあるときは rule を分けて relate の then でつなぎます。

書き方意味
notify me "..." / notify borrower "..."通知する（宛先は me か、人を指す項目。{項目} は中身に）
notify owner each of DueSoon一覧のそれぞれを、その箱の人へ
move this to 状態押された1件の状態を動かす（flow の矢印だけ）
move 項目 of this to 状態this が指している箱を動かす
move 箱 where 条件 to 状態絞った箱を全部動かす
remove this押された1件を消す（gone の通り）
go 画面 / go 画面 with this画面を移る
create 箱（下に「項目 値」）箱を作る
set 項目 to 値項目を書き換える（状態は move で）
action名 with 項目action を呼ぶ。入力は this の項目

値

create の「項目 値」と set に書けるものです。

書き方意味
this押された1件
me押した人
result直前の action の答え（relate の then で渡る。答えが無ければ、この rule は静かに起きない）
項目 of thisthis の項目の値
"文字"そのままの値
{名前}when の {…} で取り出した値
7 days from now今から（年まで入れて保存。推測しない）
状態の名前・数そのまま

do で使える道具

action の中身に書ける道具は、これで全部です。ここに無いものを書くとエラーになります。

文字

書き方意味例（テストで動かしています）
normalize X全角を半角に（数字・英字・記号）normalize t t = '１２／３' → 12/3
trim X前後の空白を取るtrim t t = ' a ' → a
lower X / upper X小文字に / 大文字にlower t t = 'AbC' → abc
split X by ","区切って集まりにsplit t by "," t = 'a,b' → ['a', 'b']
join X by ","集まりをつないで文字にjoin split t by "," by "-" t = 'a,b' → a-b
replace "a" with "b" in X置き換えるreplace "," with "" in t t = '1,980' → 1980
X contains "a"入っているか。答えは yes / no（match で分ける）t contains "締切" t = '締切は明日' → yes
X starts with "a"で始まるか。答えは yes / not starts with "Re:" t = 'Fw: 件名' → no

形

書き方意味例（テストで動かしています）
find all 形 in Xshape に当たったものを全部、集まりでcount of find all D in t t = '1 と 22' → 2
名前 of X当たりの中の、shape で名前を付けた部分n of first of find all D in t t = 'a12b' → 12
text of X当たった文字そのものtext of last of find all D in t t = '1 と 22' → 22

集まり

書き方意味例（テストで動かしています）
count of X数（length of X も同じ）count of split t by "," t = 'a,b,c' → 3
first of X / last of X最初 / 最後（空なら止まる。先に count で分ける）last of split t by "," t = 'a,b,c' → c
["a", "b", "c"]その場のリスト（do の中だけ。データとして残すものは thing に）count of ["朝", "昼", "夜"] t = '' → 3
X contains "a"（リスト）リストにその値が入っているか。答えは yes / no["朝", "昼", "夜"] contains "昼" t = '' → yes
sort X / sort X desc並べる（数は数の順）/ 逆にsort split t by "," t = 'b,a,c' → ['a', 'b', 'c']
take 3 of X先頭から3つtake 2 of split t by "," t = 'a,b,c' → ['a', 'b']
unique of X同じものを1つに（順番はそのまま）unique of split t by "," t = 'a,b,a' → ['a', 'b']

数

書き方意味例（テストで動かしています）
number of X文字を数に（1,980 や 1.5 も読める。読めなければ止まる）number of t t = '1,980' → 1980
a + b / a - b足す / 引く（一番弱くつなぐ）count of split t by "," + 10 t = 'a,b' → 12
sum of X / min of X / max of X合計 / 一番小さい / 一番大きい（空の sum は 0）sum of split t by "," t = '1,2,3' → 6
round X四捨五入して整数に（2.5 は 3）round avg of split t by "," t = '2,3' → 3
avg of X平均（空なら止まる）avg of split t by "," t = '1,2' → 1.5
abs Xマイナスを取るabs number of t t = '-7' → 7

日時

書き方意味例（テストで動かしています）
monthday of X月・日（・時・分）を取り出した当たりを "10/15 12:00" にmonthday of first of find all M in t t = '締切10/15まで' → 10/15
date of X年・月・日を取り出した当たりを "2026/10/15" に（年が要る）date of first of find all Y in t t = '2026年10月15日' → 2026/10/15
time of X時・分を "12:00" に（当たりか、時刻の入った文字から）time of t t = '開始は 9:05 から' → 9:05
add 3 days to X年の入った日付に日を足す（年の無い日付は止まる。年は推測しない）add 3 days to t t = '2026/12/30' → 2027/1/2
weekday of X年の入った日付の曜日（mon〜sun。match で分ける）weekday of t t = '2026/9/23' → wed
days until X今日から X まで何日（part の中で。今の時刻が要る）—

shape — 正規表現の代わり

見出しの下に、部品を1行に1つずつ並べます。名前を付けた部分は 名前 of 当たり で取り出せます。

部品意味
"文字"そのままの文字
space空白（1つ以上）
digits 1..2 / digits 4数字（範囲か、ちょうどの数）
letters 1..10文字（日本語も入る）
word 1..10文字・数字・_（日本語も入る）
word with "._-" 1..64英数字（ASCII）と書いた記号だけ（メールなど）
any 1何でも1文字
名前 digits 1..2取り出す部分に名前を付ける（名前 of 当たり で使う）
maybe ...あっても無くてもいい（行の残りまで）
one of "/" "-" "年"どれか1つの文字（month one of "1" "2" … のように名前も付けられる）
edge最初の行なら「数字・英字の続きから始まらない」、最後の行なら「続きで終わらない」（123-4567 が 0123-45678 の中に当たらない）
Clock / maybe Clock別の shape を名前で使う（中の名前もそのまま取り出せる）
shape Deadline
  month digits 1..2
  "/"
  day digits 1..2
  maybe Clock

shape Clock
  space
  hour digits 1..2
  ":"
  minute digits 2

エラー

ponte check が止める理由と直し方です。ponte explain E32 でも同じものが見られます。

E01 match に else が無い

なぜ止めるか 書いていない値が来た時に、何をするか決まっていないから。

どう直すか 最後に else -> 結果 を書く。宣言した状態を全部書いたなら else は要らない。

E02 until に上限が無い

なぜ止めるか 終わらないかもしれない待ちは、アプリを止めてしまうから。

どう直すか repeat ... until 〇〇 or 1 hour passed のように、回数か時間の上限を書く。

E03 action に example が2つ未満

なぜ止めるか 例が1つだと、AIが書いた中身が本当に分かっているか確かめられないから。

どう直すか 当たる例と、当たらない例（-> missing など）を最低1つずつ書く。

E04 action に else が無い

なぜ止めるか AIの中身が答えを出せなかった時の逃げ道が要るから。

どう直すか else skip / else ask user のように、困った時の動きを書く。

E05 tbd が残っている

なぜ止めるか まだ決めていないことがあるまま動かすと、AIが勝手に決めてしまうから。

どう直すか 決めて tbd を消す。決められないなら、そのパーツを使わない形にする。

E06 ## が残っている

なぜ止めるか ## は「ここは止めて」という印。書いた人がまだ引っかかっているから。

どう直すか 中身を確かめて、## を消すか #（ただのコメント）にする。

E07 when に状態を書いている

なぜ止めるか 「期限が近い」のような状態は、いつ起きるかが決まっていないから。

どう直すか when は出来事（every day at 8:00 / user taps ...）にして、状態は where か list で絞る。

E08 move の対象が絞れていない

なぜ止めるか どの1件を動かすか分からないまま、まとめて動いてしまうから。

どう直すか move this to 状態 にするか、list で1件に絞る。

E10 ぶつかる move の勝ちが決まっていない

なぜ止めるか 同じ1件に違う move が同時に来た時、どちらが勝つか分からないから。

どう直すか flow に failed > passed のように勝ちを書く。

E11 list がぐるっと自分を指している

なぜ止めるか A の元が B で B の元が A だと、中身が決まらないから。

どう直すか どちらかを thing から直接絞る形にする。

E12 入れ子

なぜ止めるか 入れ子は読む人にもAIにも間違えやすいから。1段で書く決まり。

どう直すか 中の方に名前を付けて外に出し、その名前を使う。

E13 action の約束が食い違う

なぜ止めるか example の答えや never が out の形に合っていないと、確かめようがないから。

どう直すか out に書いた形（found monthday | missing など）で example と never を書き直す。

E14 relate の then / before が一周している

なぜ止めるか A の後に B、B の後に A だと、終わらないから。

どう直すか どこかの then を外すか、条件付きの rule に分ける。

E15 relate の勝ちが両方向

なぜ止めるか A > B と B > A が両方あると、どちらも勝てないから。

どう直すか どちらか一方だけ残す。

E16 before の前が起きない

なぜ止めるか A before B なのに A が起きる道が無いと、B が永遠に起きないから。

どう直すか A のきっかけ（when）を書くか、before を外す。

E17 逃げ道が2つある

なぜ止めるか action の else と relate の else が両方あると、どちらが動くか分からないから。

どう直すか どちらか1つにする。

E18 match に無い状態がある

なぜ止めるか 宣言に無い状態の枝は、打ち間違いのことが多いから。

どう直すか 宣言の状態名に直すか、宣言に足す。

E19 who が無い thing がある

なぜ止めるか 書いていないことは誰もできない決まり。見ることもできないから。

どう直すか who に user can see Thing where ... などを書く。

E20 他の箱を指す項目に gone が無い

なぜ止めるか 指している先が消えた時に、こちらをどうするか決まっていないから。

どう直すか gone[remove too] / gone[leave empty] / gone[block] のどれかを付ける。

E21 thing の形を変えたのに change が無い

なぜ止めるか もう保存されているデータを、新しい形にどう合わせるか決まっていないから。

どう直すか change Thing to v2 に、足した項目の初期値（add memo text = ）や名前の付け替えを書く。

E22 ask ai に上限が無い

なぜ止めるか AIへの問い合わせが止まらないと、お金と時間がかかり続けるから。

どう直すか how に時間かお金の上限（limit 5 seconds / limit 1 yen）を書く。

E23 connect の失敗の逃げ道が無い

なぜ止めるか 外のサービスはいつか失敗する。その時の動きが決まっていないから。

どう直すか relate に rule名 else 〇〇 を書く。

E24 flow scene に無い画面の移動

なぜ止めるか 画面の行き来も flow と同じで、書いた道しか通れないから。

どう直すか flow scene に矢印を足すか、移動先を直す。

E25 words の訳が足りない

なぜ止めるか 片方の言語でだけ文字が抜けると、その言語の人に意味が伝わらないから。

どう直すか words ja / words en の両方に同じ名前で書く。1つの言語だけのアプリなら words を書かずに "文字" で直接書ける。

E26 名前の無いボタン・説明の無い画像

なぜ止めるか 読み上げを使う人に、何のボタンか伝わらないから（公開する時だけエラー）。

どう直すか ボタンに named 名前、画像に説明を付ける。

E27 通貨の違う money を足している

なぜ止めるか 円とドルをそのまま足すと、意味のない数になるから。

どう直すか 同じ通貨どうしで足すか、別々に出す。

E28 定義されていない名前

なぜ止めるか 無い部品・無い list・無い項目・無いアイコンを指していると、動かしようがないから。

どう直すか エラーに出た名前を、定義されている名前に直すか、定義を足す。

E29 rule に do が2つ以上ある

なぜ止めるか 1つの rule は1つのことだけ。2つあると、片方だけ失敗した時にどうなるか分からないから。

どう直すか rule を2つに分けて、relate の A then B でつなぐ。

E30 通知の宛先が無い

なぜ止めるか 誰に知らせるかが決まっていないと、誰にも届かないから。

どう直すか notify owner ... のように、人を指す項目か me を書く。

E31 書き方が分からない（do・example の手順・読めない行）

なぜ止めるか 決まった形以外は、実行エンジンが動かせないから。example の手順の打ち間違いを見逃すと、確かめていないのに通ってしまうから。

どう直すか do は ponte guide --rules の表の形で。example の手順は given / adds / at / says / taps / gets / expect のどれか。

E32 型が合わない

なぜ止めるか 無い状態・無い項目・違う型の値を、動かす前に見つけるため。

どう直すか エラーに出た候補（「todo / done」など）から選んで直す。

W09 （注意）flow の状態に rule の抜けがある

なぜ止めるか 他の状態には rule があるのに、その状態の時の rule が無い。考え忘れかもしれない。

どう直すか その状態の時に何が起きるかを rule に書くか、何もしないなら気にしなくていい。

W26 （注意）名前の無いボタン・説明の無い画像

なぜ止めるか 試作中は注意だけ。公開する時（--publish）はエラーになる。

どう直すか ボタンに named 名前、画像に説明を付ける。
